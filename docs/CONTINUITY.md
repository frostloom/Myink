# 章节开头与跨章衔接修复

2026-09-08。目标是保留前章现场的因果关系，减少机械重复的开场；不靠随机换视角或禁用一切「醒来」强行制造差异。

## 原因与实现

- 原召回取整书最新章节。目标章已存在或已有后续章时，最新章不是前章，章尾信息被整段跳过。现在按 `chapter_seq - 1` 取前章，章尾窗口从 300 扩至 800 字。缺章时不拿更早章节冒充直接前章。
- 新增最近 4 个已确认历史章的开头，每章最多 220 字，去掉导出标题与分隔线。章头只作为差异化参照；章尾才是接续位置。近期和混合召回的事件不再把本章旧稿/未来事件当作前情。
- 规划增加 `transition`：章尾逐字引文、未完成动作、第一拍新进展和转场线索。程序核验引文来自召回原文；跳时/切景必须给出桥接。旧 checkpoint 的无 transition 计划保持兼容。
- 写作、审核、修订共享章尾与近期章头。审核明确检查重复入场、请求/危机被跳过、无交代的时空切换和近义改写的重复开场，输出跨章原文证据及具体建议。合理同场景接续、转场、呼应和昏迷恢复可以通过。
- 修订保留计划、大纲、文风、字数和人物信息，随后重新抽取记忆、校验、审核，避免新稿配旧记忆。修订轮数用尽后若仍未通过语义审核，转待确认，不自动放行。
- 章头属于可选上下文，超预算时从较早章节起移除；章尾、正文和硬约束仍保留完整，必需内容超限则显式报错。
- 写作/审核请求按实际工具 schema 大小预留预算，再额外保留纠错/工具轮空间，避免硬编码的 1,000 token 预留装不下工具说明。

## 验证

`tests/test_continuity.py` 覆盖重写时前章查找、缺章边界、标题清理、各节点前情一致、引文核验、修订后的记忆刷新、语义审核失败转人工与明确续跑。`tests/test_context_budget.py` 补充修订提示词预算回归。

本次验证：独立 PostgreSQL/Redis/RabbitMQ 临时容器中的全量 Python 回归为 518 passed、5 个既有 xfailed；随后工具 schema 预算修正通过 `test_flow.py`、`test_continuity.py`、`test_context_budget.py` 共 59 项集中回归。反复运行共享 demo 测试会积累记忆，全量回归应按 `scripts/ci-local.sh` 使用全新临时数据。API/Worker 和网关镜像已重建启动，运行容器与工作区提示词源码哈希一致，网页及 `/health` 均返回 200。

真实模型小样本由 `scripts/eval-continuity.py` 复现，需显式 `--live`，使用已配置 API key，产生正常 API 用量，不读写小说数据库：

```powershell
python scripts/eval-continuity.py --live
```

此次使用 deepseek-v4-flash：重复进门、跳过危机、机械重复开场 3 个合成反例均判 rewrite；自然接续、合理恢复/跳时 2 个对照均判 pass。另完成一次规划 → 约千字正文 → 审核，新稿从妹妹递螺丝刀接续，审核通过。完整输入、输出、模型与 token 用量见 [评测记录](evaluations/continuity-smoke.json)。

这是 5 个受控片段和 1 次短章生成的冒烟验证，不能据此宣称长篇重复率下降了某个百分比。语义判断依赖模型，仍可能漏报或误报；下一步应固定不同题材的连续 10–20 章样本，由人工盲评接续、重复和转场质量，并记录重写次数与成本。现有小说不会被自动重写；本次修复作用于之后的新生成和用户发起的重写。
