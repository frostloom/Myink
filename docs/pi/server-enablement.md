手动部署由用户优先。先停发新候选、取得共同锁，再记录 commit/image/config/deployment_id/generation/owner/maintenance_epoch，更新稳定基线。相同 SHA 也必须有新 generation；旧 Pi 会话与旧恢复回执不具有覆盖权。pending 动作先核对现实身份和实际副作用，禁止盲目重放。新人工/模型/配置变更使比较混杂，重新冻结基线。

02:00–06:00（Asia/Shanghai）为未来窗口；05:30 停止新候选。PRE 不成功不得产生候选；发布后 POST 欠账阻断后续普通发布，但恢复不依赖模型额度。06:00 的调度选择只表示期望开放，必须另有真实入口/消费者回执。备份保留数据库、角色、加密材料、附件、配置、证书及账本一致性水位；完成完整且独立的恢复演练后才具备恢复资格。损坏后重验撤销资格，终态失败不能原地改成成功。

升级遵循[版本升级规范](pi-version-upgrade.md)：固定精确版本和 lock/hash，在私有 E 盘副本验证 RPC、工具、退出与预算，再受控切换；保存旧版本与会话身份。Engine/config 切换建立新绑定会话，共享原试验预算，不清除未知预留。管理员的可替换 Engine 接口已实现，当前实际引擎仅 Pi；没有第二个实际引擎的运行时替换验证，也没有两个假引擎的合同测试。

政策更改由可信宿主审查，禁止模型放宽路径、额度或开关。首次试验累计最多100请求/10元估算，所有角色、重试和压缩共账；未知 usage 保留最坏预扣。最终累计6请求，已扣或预留8095752 microyuan（已知估算46344、未知预留8049408）；实际账单未知。剩余1904248小于下一次最坏预扣2016384，禁止继续请求。付费 plan 的2次HTTP和4次只读工具调用后因 cache-input 用量转换未通过现有严格解析器校验停止，未获批计划，未开发或发布。SQLite 版本升级先停止控制器，用一致性备份覆盖活动 WAL，在副本演练迁移；不删除历史以绕过去重。参考[失联与通知排查](notifications.md)。
