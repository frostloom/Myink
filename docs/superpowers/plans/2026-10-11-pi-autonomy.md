# Myink Pi 自主迭代实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在独立本机环境验证 Pi 分析、规划、开发、测试、候选发布、恢复和次日比较的完整闭环，为后续服务器启用提供证据。

**Architecture:** Pi 通过官方 RPC 做判断，项目控制程序执行预算、资源隔离、备份、发布和恢复。控制程序使用 Python、SQLite 操作账本与类型化工具，业务任务暂停状态仍由 PostgreSQL 承载。先验证确定性协议，再建立独立服务，最后安装 E 盘 Pi 并进行有界实测。

**Tech Stack:** Python >=3.11、现有 Pydantic/SQLAlchemy/httpx/pytest、SQLite、PostgreSQL 16 + pgvector、Redis 7、RabbitMQ 3.13、Docker/Buildx、Linux cgroup/systemd、Pi v1.1.0 与 Node >=22.19；不安装 ML/embedding extras。

**Spec:** [已确认的总体设计](../specs/2026-10-10-pi-autonomy-design.md)。代码基线 `299672ca9b36e3cbc27bca5ae0aad0c640d2fcbf`；日期 2026-10-11；状态：用户于 2026-10-11 批准按子智能体逐任务开发和独立审查执行，授权按验收批次提交并推送 GitHub；当前不授权服务器启用。

## Global Constraints

- 实施仅在 `codex/pi-autonomy-design` 隔离 worktree；保护 `E:/github项目/Myink` 主工作区的既有修改。
- 新 Pi、Node、依赖、缓存、会话和私有证据位于 `E:/tools/myink-pi/`；当前不在服务器安装 Pi、不改 cron、不执行线上候选部署。
- 首轮所有真实模型 HTTP 请求累计最多 100 次、估算 10 元，跨日不重置；未来服务器每天 100 次、估算 10 元不在本轮启用。
- 模型读取 `PLATFORM_MODEL_API_KEY/BASE_URL/NAME/PROTOCOL`，当前为 Anthropic、`deepseek-v4.1-flash`；价格未得到该服务可信配置前不发真实请求。
- 分析、压缩、重试、探测、评审和业务实验共用账本；预扣最坏估算费用，未知结果保留预留；恢复不依赖模型余额。
- 未来维护窗口为 Asia/Shanghai 02:00–06:00；15 分钟收尾初值、05:30 停止新候选路径、06:00 开放；本机用虚拟时钟验证。
- PostgreSQL、Redis、RabbitMQ、维护入口保持在线；拒绝新任务，现有任务在已验证节点暂停，开放后只恢复本轮维护暂停的任务。
- PRE → 分析/开发/测试/串行构建/发布 → POST；没有发布不强制重复 POST。旧 03:17 备份触发器本轮不变。
- 用户决定新功能；Pi 改善稳定性、成本、速度、写作质量和体验。未达标后继续归因和修正，不终止长期循环。
- Pi 计划软目标：1 个假设、1 个行为、通常 <=3 个生产文件/150 行；每个部署步骤兜底 <=8 个跟踪文件/300 行生产增删，每天最多一次普通发布。
- 用户部署优先；共同锁、deployment_id、generation、owner、maintenance_epoch 与实际镜像共同校验；旧恢复程序不得覆盖新的人工部署。
- Pi 384MiB/0.5 核；测试整组或 BuildKit 1536MiB/2 核、额外 swap <=256MiB；两者互斥。宿主可用内存连续 10 秒低于 512MiB 时中止重任务。
- 磁盘门槛为本轮预计新增峰值加 5GiB；普通工具/模型 120 秒、备份 600 秒、整组回归/单镜像 45 分钟，同时受阶段绝对期限约束。
- 配对至少 5 组；线上同型完整任务 <20 为证据不足，尾部样本 <100 不以 p95 下结论；人工/模型/配置变更重新建立基线。
- GitHub 先用本地 bare remote，通知先用捕获服务，云告警先用故障信号替身；不发真实邮件或短信；按用户最新授权逐项本地提交，验收后批次 push 当前隔离功能分支到真实 GitHub，不 merge main、不部署生产 Pi。
- 初始化工程不冒充每天一次的小优化；每项完成有独立验证记录。SKIP、未运行、被阻塞均不报通过。

## Review Focus

1. 操作完成后进程崩溃、回执尚未保存：重启先对账，不能重复扣费、发布、迁移或发信。对应 A1/A2/A6/B10/B13。
2. 同一 SHA 被人工重新部署、旧 watchdog 仍活着：身份更新使旧动作失效，保留人工版本与维护责任。对应 A5/B13。
3. Worker 在维护中重启，消息尚未物化或正在 ACK/重投：保持消费屏障并核对持久记录，不丢任务、不重复正文。对应 B8/B9/B10。
4. Pi 通过工具、重试、压缩或嵌套进程调用模型：所有出站必须受同一额度约束，不能读凭据或修改控制政策。对应 A2/B7/C14/C15。
5. 缺少 usage、样本或版本窗混杂：报告未知/不足/混杂，不能当零费用或改进；未达标仍生成诊断。对应 A4/C16/C17。

按 A → B → C 执行。子计划共享本文件的约束；任务代码放 `ops/pi/`，业务侧只增加必要的维护协议与观测挂点。`ops/pi/tests/` 单独收集，避免根 `tests/conftest.py` 导入业务数据库使离线测试依赖活库。业务集成测试仍放 `tests/` 并使用独立服务。不重构现有管理面板、不新建用户产品功能。

开发语言统一为 Python 控制程序；Pi 扩展为单个 TypeScript 文件，仅桥接受控工具。控制对象、接口、验证命令由各任务定义，不引入通用 Agent 平台。运行目录分为 `runtime/`、`cache/`、`pi-home/`、`sessions/`、`state/`、`evidence/`、`backups/`，全部在 E 盘，凭据只由信任侧进程读取。

计划要求的新命令目前尚未实现，不能把命令列在文档中视为已经测试。新包和可执行入口随各自任务建立。实施时每步记录红测、绿测、审查和阻塞；本轮计划编写不运行产品测试。

本机测试命令统一使用进程级缓存配置：`PYTHONPYCACHEPREFIX`、`TEMP/TMP/TMPDIR` 和 `PYTEST_ADDOPTS` 的 cache_dir、basetemp 指向 E 盘运行目录，basetemp 每次使用新 run_id；不修改系统环境变量。安装 npm 设置 E 盘 cache；新 WSL 发行版自身磁盘亦在 E 盘。文中 pytest 命令省略这组公共前缀，由实验 runner 一次设置和验证，不能默认写入用户目录。并发调研可读文件，基础设施测试按唯一实验锁串行执行。

## 初始化与后续启用的分界

本轮建立本机实验工具和 Linux 受限环境。优先使用 E 盘独立 WSL2 发行版 `MyinkPiLab`，其磁盘、Docker 数据和依赖均在 E 盘，不更改已有发行版、全局 `.wslconfig` 或默认 Docker context。WSL2、虚拟化、systemd/cgroup 条件不满足时停止设施安装并报告具体前提；不得自行重启主机、关闭现有 WSL 或把限额测试降为无约束运行。

真实服务器启用另写计划：实际容量校准、稳定维护协议初始部署、备份触发器交接、离机目的地、GitHub App、邮件收发和腾讯云独立告警均需要专门回执。本机通过不是这些项目已完成。后续启用不以每天让用户确认 Pi 普通优化为前提；首次安装和权限配置确认属于初始化。

## 总体验收与交接

- [ ] A：无活库、无模型网络即可完成所有控制测试，人工基线与账本重启证据可读。
- [ ] B：独立 PG/Redis/RabbitMQ、合成正文；暂停/续跑、恢复、消费屏障、并发和两镜像冷/热构建有真实回执；依赖不可用记 blocked。
- [ ] C：累计请求和费用账本可追溯；Pi 完成一个可复现小问题的规划到比较；注入的失败触发自主诊断；主工作区和线上均未变。
- [ ] 完整业务验证：按现有 CI 执行 Python 全量、案例校验、契约导出检查、前端 lint/test/build、两镜像构建；新增 ops 测试纳入 CI。Go 仅在实际适用并修改时运行，不把主工作区未提交的 `gateway/` 纳入本轮。
- [ ] 独立审查整个初始化分支，生成 `docs/evaluations/pi-local-trial/report.md` 与脱敏回执索引，列出运行、跳过、阻塞、资源峰值、实际费用和未启用云能力。
- [ ] 当前初始化成果 commit/push/合并/服务器部署遵循用户对本轮的明确授权；计划中的提交点是建议保存点，不自动沿用旧 P2 发布授权。

执行方式推荐逐任务子智能体开发与独立审查，原因是消息、备份和恢复的错误可能在模型预算耗尽后才暴露。也可以由主代理依次实现，最后独立审查。两种方式都不并发启动固定端口或共享基础设施测试。
