# Pi 本机完整接力入口

目标：把已经验证的选题、任务包检查、冻结审查和开发协调器接成仓库内可重复使用的命令，随后通过真实模型接力验收。用户已授权自主推进、模型请求和阶段推送；不合 main、不部署。

1. 提取无输出目录依赖的模板预检，保持旧适配器行为。用失败测试验证取消、身份、账本和实际审查边界。
2. 新增严格私有配置的 `local_cycle`：默认只读检查，显式执行一次有限 ACTUAL 周期，输出原协调器 receipt。输入、各阶段输出、控制/费用账本分离；重用根目录拒绝，禁止自动重试和自动采纳候选。
3. 补充异常路径和命令行说明，运行相关及完整 Pi 测试。
4. 生成新的真实任务、当前控制代码快照及独立审查，使用入口执行真实付费接力；核验候选、费用、关闭与清理。
5. 独立代码审查、必要修复、阶段提交推送。

验证：先观察针对性测试失败，再实现通过；全量 Pi 测试及 Node 协议检查；真实接力证据与产品回归独立记录。原历史未知费用保持不变。静态测试提示不能替代隔离实际基线。

范围决定：入口采用一次性输出根目录；再次执行同一根目录在任何模型调用前拒绝。底层协调器现有终态重放语义不变。这样不把跨进程单调时钟冒充可恢复的执行授权。
