# Pi 人工确认夜间工作流实施计划

Spec: ../specs/2026-10-30-pi-human-gated-nightly-design.md

用户已直接确认流程并要求加快，连续执行，不逐阶段提问。现有 worktree/分支不变，旧自动发布演练停止并保留证据。

## Task 1 — 持久轮次与人工门禁

先测试后实现。绑定原 manager 状态记录单轮与冻结产物，等待状态跨天/重启/并发不重入；批准和真实部署分离。原 manager 严格拒绝外来operations，故审批元数据用独立且不兼容费用/manager的schema/user_version保存，不建立第二任务队列/执行器/费用scope，实际调度和付款仍只走原manager/账本。验证拒绝副作用、摘要漂移、部署未知及旧候选继承。

## Task 2 — 真实入口和定时触发接线

查清现有 source/analysis/coordinator/manager/candidate completion入口；在昂贵或读取新指标前检查门禁。已有候选优先进入等待，不启动下一任务。修改固定定时器/根封存运行包入口，等待时只做轻量状态检查。保持原身份/账本/模型许可，系统重启不追赶未确认轮次。

## Task 3 — 本地镜像与对比包

复用既有独立开发/审核/固定输入评测，绑定真实源码、镜像ID/归档、次日对比参数和审计；本地准备后停止。无人工批准，不触发GitHub/镜像仓库推送或服务器部署。

## Task 4 — 验收与交付

相关单测、跨日重启/并发与原账本隔离、一次完整有界隔离工作流、实际产物检查；一次新上下文最终审查和一次作者修复。交付可审查操作包和明确未发布状态，最后一次人工批准再执行获批推送/安装/发布。实际新版本观察只在用户发布后开始，不把计划当结果。

- Task 2：本地已接入闭合nightly入口与单一定时器模板。完成候选优先于新任务；真实执行仍只调用原source coordinator和原manager；manager只可执行本轮绑定任务。旧7个定时器保持停用，新模板未安装。部署后的观察/对比收尾接线仍待完成。
- Task 3：本地完成源码/原SDK证据核验、快照、镜像适配、补丁、评测、工具流、审计和相对次日计划的封存。真实Docker镜像构建/归档适配器已通过独立隔离验证；整包驱动已通过原manager真实格式的隔离测试，尚未对服务器已有候选执行实际整包准备。

准备私有包时，沿用原开发前FileReview与独立冻结checker，完成完整原manager/SDK/工具/费用核验；不为准备文件额外增加一次付费模型复审。最终产物仍必须由人批准后才可推送或部署。
