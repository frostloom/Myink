# 第三轮端测反馈：统一导航、紧凑详情、自动规则

用户纠正第二轮方案：导航应统一固定尺寸并悬浮在视口最左侧，所有页面一致；题材完整展示但不能将短字段逐行展开造成大量留白；创作/表达规则应自动选用，旧书也不能显示没有资源。

## 实施与验收

1. 统一用户、管理员和各页面外壳的固定导航尺寸及正文占位。桌面距左/上12px，高视口减24px，宽统一变量；窄屏保留可用的固定60px顶部导航并预留正文位置。验证跨页面等尺寸、滚动前后位置不变、内容不遮挡。
2. 题材详情保留全部字段；名称与钩子成对短行，相关字段分栏，小屏单列；减少重复标题、内外间距。使用完整内置修仙题材而不是空数组样例端测，检查高度和溢出。
3. 后端首次补齐默认创作规则与表达规则，优先个人版本，写入冻结作品快照；GET/capture使用租户事务、项目行锁，幂等初始化。已有选用/本书覆盖、题材与已入队任务不替换；管理员后续更新仍需明确采用。新增默认初始化标识避免今后GET无意追随目录变化。前端标注自动规则并保留编辑能力。
4. 针对性RED/GREEN、独立交叉审查、前后端回归、lint/build与三引擎真实布局检查；通过后备份并使用专用迁移服务更新localhost，远程不变。

## 分工

navigation负责共享导航与外壳，backend负责默认规则真实落库，short_chat负责自动规则前端语义；主代理负责完整题材紧凑展示、综合验证及本地更新。保护前两轮未提交改动，不涉及Pi，不自动推送。
