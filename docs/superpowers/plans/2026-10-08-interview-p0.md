# 面试准备 P0 实施计划

目标：整理应用、平台工程、效果优化的完整路线，交付可离线展示的真实历史案例，修复已发现的工具边界，并使用用户级 Archify 生成项目流转图。

范围：沿用当前编排、快照和前端，不增加新后端服务；历史记录不冒充当前版本评测；不调用付费模型，不改生产数据，不提交、推送或部署。保留开始时的八项未跟踪文件/目录。

实施顺序与验证：

- [x] 路线图与面试说明：更新 README、DEMO，标注旧 BACKLOG 的历史性质；逐项链接到当前代码或历史记录。
- [x] 工具回归：先证明单轮多调用超预算、缺省章号未绑定；修复后验证零预算、多轮、协议完整性与参数不被修改。
- [x] 离线案例：从既有合成题材真实模型记录生成 HTML，显示完整已留存节点、人工拒绝说明、来源哈希与证据缺口；验证可重建和输入不变。
- [x] Archify：安装到用户技能目录，按已提交代码固定源证据，生成中文流转图、JSON 和验证回执到项目目录；区分自动验证和视觉检查。
- [x] 验收：聚焦 Python 回归、产物检查、差异审查；记录无法执行的检查。只有修改前端源代码才运行前端三项检查。

工具修复设计：模型消息中的每个 tool_call 都收到结果。预算内执行，预算外回 TOOL_BUDGET_EXCEEDED 并记录 skipped，然后结束工具阶段。零预算直接进入无工具最终轮。人物/事实工具缺省章号由当前 ChapterState 绑定，显式历史章号保持原值。

Archify 的源证据固定到 HEAD，未提交修复另见 P0 验证记录，不能把工作区字节当成已提交证据。
