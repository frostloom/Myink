# 文风提取纳入写作资源 Implementation Plan

> 本计划由当前代理按 executing-plans 流程执行；验证先行，不自动提交或部署。

**Goal:** 在写作资源中提取文章文风，用户保存为本人资源，管理员可选择保存个人版本或发布平台版本。

**Architecture:** 复用现有文章提取接口和受权限保护的个人资源、管理员资源/发布接口；结果遵循资源已有 profile 格式、版本与项目快照机制。旧文风库继续可访问并支持将个人档案复制到资源目录；不删除或自动迁移历史数据。管理员发布失败保留草稿并允许仅重试发布，防止重复创建。用户切换或卸载后停止后续操作。

**Tech Stack:** Vue 3、现有 FastAPI 写作资源与文风提取接口、Vitest、pytest。

## Global Constraints

- 个人内容通过服务端用户身份隔离；平台创建及发布由服务端管理员检查和审计。
- 无密钥、新模型、强制历史数据修改或额外部署；不破坏既有未提交工作。
- 提取失败显示降级提示，保存前可查看并编辑档案；管理员显式选择发布范围。
- 长短篇的现有资源选择与旧文风选择保持可用。

## Tasks

1. 补充失败测试：用户提取/编辑/个人保存；管理员公开发布与失败后重试；账号切换与私有权限；旧档案复制。
2. 在写作资源页实现提取与个人保存、管理员发布、旧文风复制，复用现有服务端授权。
3. 检查长短篇真实运行时如何使用选中的资源文风，并补充端到端或消息级测试；修复发现的问题。
4. 运行相关前后端测试、前端 lint/build、契约和差异检查；记录未运行的检查。

## 实施记录与取舍

- 长短篇的建书选择均读取已发布平台文风及本人文风；资源选择以短且稳定的标识兼容旧短篇会话字段，已保存旧标识仍可读取。
- 建书选择写入作品资源快照；显式切换文风后由资源快照接管，取消也不会恢复旧风格。接管标记保存在既有项目资源 JSON 中，旧快照未带标记时原优先级不变。
- 管理员发布响应中断时核对公开发布内容，避免重复创建和误报；原文风通过受服务端用户隔离和唯一约束保护的幂等接口复制，不自动修改或删除旧数据。
- 原计划中的账号隔离、发布失败、切换、清空、长短篇实际消息与并发导入均有针对性测试。

## 验证记录

- 真实隔离 PostgreSQL、Redis、RabbitMQ 全量 Python：2295 passed、1 skipped、5 xfailed、2 subtests passed；跳过和预期失败不计为通过。
- 前端全量：共享测试 207 项、Vue 测试 821 项通过；后续提取/幂等/账号切换的小幅调整另有 7 项针对性测试通过。前端 lint 无错误、构建及类型检查通过。
- 实测同一旧文风的两次并发导入只创建一个个人资源；普通用户不能发布平台资源，已发布平台文风和本人文风可用于长短篇；旧作品切换再取消时旧文风不复活，而已捕获的旧任务快照保持原行为。
- 独立只读审查提出的问题已修复并复查；API 契约重导出后一致，隔离服务和临时卷已清理。
- 以上为本地结果；未提交、推送或部署。
