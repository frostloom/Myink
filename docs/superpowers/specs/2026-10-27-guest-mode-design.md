# 游客模式设计

状态：用户于 2026-10-28 确认实施；本轮不自动提交、推送或部署。

## 目的与已确认需求

未登录提示和登录页增加“游客体验”。游客可使用普通用户的作品、建书对话、写作、资源编辑、设置、导出等功能，不能访问管理员能力。短篇累计 2 次生成额度，长篇累计 10 章生成额度。用户已明确：按生成次数计，主动重写再次扣额度，同一次任务的系统自动重试不重复扣。

额度用尽后仍可查看、编辑和导出已有内容；需要新增 AI 写作时提示“游客体验额度已用完，注册账号获取更多写作额度”，并提供注册入口。不能暗示注册后无限额度；正式账号遵循原有普通用户规则。

## 建议的实现决策

以下实施决策随完整方案于 2026-10-28 获用户确认。

### 身份与 IP

为每个浏览器会话创建独立的普通权限游客账号，用随机、不公开的持久化游客凭证恢复身份，保留现有租户隔离。认证接口、会话响应标识 is_guest，权限仍 role=user。游客凭证与常规 JWT 续期边界需要支持刷新后继续使用；不能允许客户端任意指定或升级账号角色。

IP 仅用于服务端累计额度分桶，绝不用于返回同 IP 的其他游客身份或作品。同一公网 IP 的不同浏览器共享额度，作品互不可见。清除凭证会失去该游客作品的恢复入口，但不能重置 IP 额度。注销/重新体验、删书、日期变化和重启服务均不重置额度。

使用现有由 Caddy 覆盖写入的客户端 IP，规范化地址后以服务端密钥 HMAC 存储账本键；不信任浏览器自报 IP。不记录无效/unknown IP 到统一可写桶，无法可靠取得地址时拒绝创建游客会话并给出可重试提示。保留现有边缘信任边界，部署时确认 API 未暴露公网。

身份记录初始 IP 分桶，后续游客写作对初始 IP 和当前 IP 的不同分桶同时校验与记账，避免持有同一凭证切换网络重新获得额度，或拿其他网络的游客凭证绕过当前 IP 已使用额度。锁按固定顺序获取以避免死锁。两个键相同时仅扣一次。

仅凭 IP 无法识别“换网络并清除凭证”的同一自然人。共享网络会共享体验额度，这是本方案的产品限制；不新增设备指纹采集。

### 额度与任务一致性

新增持久化游客额度账本和操作记录，不复用现有按建书扣次数的平台额度。游客体验额度是单独明确的额度，不能再被平台免费建书次数提前阻断，但仍遵守普通用户的并发、速率、单任务预算及模型安全限制。

在统一写作任务准入处进行事务原子校验和占额，覆盖短篇生成/重写、长篇单章、批次、重写、重规划后写作、局部修订等 AI 写作入口；批次按请求的章数占用长篇额度，超出余额整批拒绝，前端提示减少章数。短篇不论内部拆成几节，都按一次完整生成扣一次。

一个被接受的新写作操作只计一次，规划确认、暂停恢复、SSE 重连、worker 重投和系统内部审稿修订均不能重复扣。人工启动的新重写/修订必须新计一次，不能通过复用旧 task_id 绕过。单纯查看、手动编辑、导出和确认保存不扣额度。建书聊天与设定/大纲准备不扣写作额度，但受现有调用限流和预算限制。

额度在任务被接受时消耗；校验失败或确定未入队的失败释放预占。任务已被接受后失败/取消不自动返还，避免反复触发模型再取消获取无限额度。处理数据库与消息队列之间的失败窗口：重试必须幂等，只有明确未发布的操作可以释放，消息发布结果不确定时不直接返还额度。操作记录持久化并可审计。

暂停后的首次继续、规划确认、仅完成存储或摘要等不重新生成正文的断点续跑保留原占额。失败后由用户手动重试并重新执行已经尝试过的正文生成/修订节点，视为新的写作操作，重新扣额度；系统自动重试仍属于原操作。不能只依据 task_id 相同就免扣，需结合操作类型和已执行阶段判断。额度用尽不阻止原已接受操作的自动重试、首次执行未完成阶段及确认保存。

### 注册与登录

从游客会话发起注册时升级当前游客账号，保留作品、资源、对话与设置；校验现有邀请码、用户名和密码规则，注册失败不影响原游客身份。升级应撤销旧游客恢复凭证与旧令牌，避免旧浏览器凭证在升级后获取正式账号权限。IP 游客额度保留，不因注册而重置。

登录已有账号按现有登录流程切换，不自动把游客作品合并到已有账号；切换前沿用未保存提醒。游客不能使用修改密码等账号操作提前变成正式账号；账号页明确引导注册。普通功能与账号升级能力应分开判断。

## 界面

未登录提示提供“登录/注册”和“游客体验”。登录页提供同一入口，解释短篇 2 次、长篇 10 章，按生成次数计算且同 IP 共享额度。游客标记及两类剩余额度在账号区域或写作操作附近可见，不改变固定导航布局。

创建游客身份、读取额度和提交写作均有 loading、防重复提交及失败重试提示。服务端不足错误统一转成带注册入口的提示，保留当前草稿，不跳走或覆盖输入。注册成功保留当前作品上下文。

复用现有 Vue 组件和主题 tokens，无 React、Pi 或管理员功能扩展。

## 验证与交付边界

测试先行：游客认证/凭证恢复、跨用户隔离、同 IP 多会话共享配额、刷新/清理凭证不重置、规范化 IP 与边缘伪造头、并发最后一个额度、批次超额、短篇和长篇分开计数、用户重写和系统重试区别、失败窗口与幂等、零余额时继续完成保存、注册升级保持数据和撤销旧凭证、邀请码失败保持游客。

前端覆盖未登录入口、加载/错误状态、剩余额度、注册引导、草稿保护、长短篇切换与用户身份缓存隔离；运行 lint/test/build 和真实浏览器场景。数据库/队列集成使用隔离环境，不使用生产数据或付费模型调用。更新 API 契约并通过契约门禁。

## 实施前审查

已完成独立 builder check。审查指出人工失败重试与系统自动重试必须区分；本设计已明确前者如重新执行已尝试的正文节点则重新扣额度，纯恢复/首次继续未执行阶段不重复扣。此规则作为实施建议一并交用户确认。
