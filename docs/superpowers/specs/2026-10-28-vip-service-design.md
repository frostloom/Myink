# VIP 服务设计

用户已确认开始，第一版由管理员手动开通/取消 VIP，不接支付与自动续费。

- 在 codex/vip-service 的独立 worktree 实现，不提交、推送、合并、发布；不修改 Pi。
- RabbitMQ 使用独立普通/VIP FIFO 队列；每个 worker 按可配置 VIP:普通权重轮询（默认 3:1，权重各 1–10），空队列让出容量。普通任务获取调度机会，不承诺完成时间 SLA，不抢占正在进行的模型请求。
- 保留旧主队列消费以排空升级前消息；新延迟队列分别回投对应等级。保留 publisher confirm、重试、死信和测试前缀隔离。
- 批次在完成章、进入下一章前持久化 checkpoint 并重新排队；保持同一 task/thread、配额、并发占位，不重复计费。
- 模型增加最低会员等级（normal/vip，旧记录默认为 normal）；普通默认沿用 model_routes，新增 vip_model_routes 覆盖。VIP 可用两级模型；普通用户不能使用 VIP 专用模型，包括隐藏默认、旧选择、降级、失败回退路径。
- 管理员在模型编辑中设置最低等级，在模型分配中设置 VIP 各环节默认模型与队列权重，在账号详情开通/取消 VIP。角色与会员等级分离。
- 所有模型目录、保存、就绪检查和调用使用服务端账号等级；权限失败不能回退到环境凭据绕过策略。
- 模型请求继续由后端发出；本期不新增模型级故障回退链，保持现有请求重试机制，所有实际选用模型都必须经过等级校验。

验证：先失败后通过的模型权限、会员管理、持续流量调度、空队列借用、重投、批次 checkpoint 测试；前端交互测试；完整 Python 回归及前端 lint/test/build；新 reviewer 独立审查。
