继续 RANKINGS-MCP-SWAP-PLAN 的原目标：真实榜单、安全接入、失败明确降级。先交付可独立验证的客户端防护，不将“准备好接入”冒充“真实换源完成”。

## 本次安全目标

- 默认发现仅接受当前已知 source 对应的精确工具名；未知 source 或工具不靠 `rank` 子串猜测。
- 显式 tool 必须存在，并且有按工具名定义的参数映射才能调用。覆盖为 community 工具时不能携带 qidian 参数。未知工具不得以空参数试调用。
- 每一条带嵌套榜单集合的分类容器都排除；包括顶层、包装层及与真实书籍混合的返回。单条容器不展开为书籍。
- 保留现有书籍 allowlist/字段限制、样例标识、按用户隔离缓存和身份校验。
- 连接异常/取消继续降级，但文案不得断言一定是用户取消。
- 暂不变更已有 URL/source 配置或默认值；不改环境页、出站守卫、Compose、依赖或数据。这避免在 sidecar 尚不存在时发布必坏的默认地址。

## 后续解除条件

完整许可证得到确认或完成独立且正确的适配；目标 ECS 真实可达；真实 MCP get_ranking 返回解码书名；资源指标实测。届时再实施 ranking_id 配置及 A2 只读运维地址方案，保持模型地址守卫不变。
