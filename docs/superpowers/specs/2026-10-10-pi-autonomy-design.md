# Myink Pi 自主迭代设计

设计日期：2026-10-10。最近修订：2026-10-11。状态：用户于 2026-10-11 确认书面设计；[实施计划](../plans/2026-10-11-pi-autonomy.md) 待审阅，实施和模型实测尚未启动。

Pi 作为 Myink 的持续维护负责人，自主完成数据观察、原因分析、优化计划、开发、测试、发布和效果复核。它优化现有产品的稳定性、成本、速度、写作质量和体验；新增功能由项目所有者决定。先在独立本机 worktree 验证整个流程，通过验收后才进入服务器部署阶段。

本设计采用 Pi 官方接口、少量项目扩展和外部调度程序。Pi 做需要判断的工作；程序执行资源限额、备份、部署归属校验和故障恢复。当前目标不包含修改 Pi 核心循环。

## 已确认的约束

| 项目 | 约束 |
| --- | --- |
| 自主范围 | 现有产品全面优化；新增产品功能进入用户决策清单 |
| 持续迭代 | 次日未改善时自主归因、补证据或修正方案；不因此终止长期工作 |
| 用户优先 | 用户本地开发与部署优先，Pi 不能长期占用发布锁或覆盖用户新版本 |
| 维护窗口 | Asia/Shanghai 每日 02:00 至 06:00；维护页显示开放时间 |
| 在途任务 | 禁止新增任务，活动任务限时收尾，超时在经过验证的节点暂停，开放后继续 |
| 数据库 | PostgreSQL 持续在线，允许 Pi 查询分析；测试不得使用生产库 |
| 备份顺序 | 更新前备份，之后执行 Pi 重任务；发布后再备份，不与构建来回切换 |
| 构建顺序 | Python 镜像和包含前端的 Caddy 镜像串行构建；API 与两个 Worker 复用 Python 镜像 |
| 小步更新 | 制定计划时就控制目标与范围；大任务先划分可独立验证的步骤，允许跨日完成 |
| 本机模型预算 | 第一轮所有实测累计最多 100 次请求、估算 10 元，跨日也不重置 |
| 服务器模型预算 | 未来每天最多 100 次请求、估算 10 元；与网站写作额度分别统计 |
| 模型与数据 | 使用现有内置模型服务；允许真实业务正文和会话参与该服务的分析 |
| 安装与隔离 | 新安装的 Pi、依赖、缓存和会话放 E 盘；保护现有主工作区；当前不安装到服务器 |
| GitHub | 每轮留存分支、提交、PR 与结果；满足发布条件后自动合并和部署 |
| 通知 | 开发日报使用邮件；服务事故使用真实故障告警，不把日报伪装成告警 |

## 当前基线与复用入口

设计代码基线为 `299672ca9b36e3cbc27bca5ae0aad0c640d2fcbf`。线上业务镜像 revision 为 `c1f7a84`。2026-10-10 的只读采样显示：宿主内存 3723MiB，可用 2469MiB，交换空间 1987MiB；API 与两个 Worker 当时合计约 352MiB。该采样不是峰值或未来容量保证。

现有备份由每日 03:17 的 `backup.sh` 触发。新编排完成本机验收后统一接管备份，再移除旧触发器，不能先取消唯一可用的备份任务。

| 入口 | 可复用内容 | 需要补足的能力 |
| --- | --- | --- |
| `src/myink/api/routes_admin.py`、`src/myink/models/runs.py` | 费用、token、耗时、失败与重试记录 | 真实部署身份、窗口化快照、配对比较与样本缺失标记 |
| `src/myink/task_budget.py`、Worker、checkpointer | 任务预算、状态与工作流恢复 | 维护专用暂停协议、任务及队列对账、发布后的恢复验证 |
| `scripts/evaluate.py`、`evals/`、生成对照脚本 | 固定案例、隔离守卫、调用预算与证据归档 | 平台模型适配、自动评审口径、版本绑定与公平对照 |
| `scripts/backup.sh` | 在线 dump、失败检查、临时文件与压缩验证 | 唯一执行者、manifest、配对留存、恢复演练与离机回执 |
| `scripts/ci-local.sh`、`.github/workflows/ci.yml` | 核心回归、契约、前端和镜像检查 | 可选择独立资源、重任务整体限额、准确记录跳过状态 |
| 现有 `.env` 配置 | `PLATFORM_MODEL_API_KEY/BASE_URL/NAME/PROTOCOL` | 统一评测与 Pi 的配置来源，避免继续依赖过期的专用 DeepSeek Key |

现有 consumer 的 SIGTERM 是等待当前处理结束，不等于经过验证的维护暂停。重试与延后路径存在 ACK 后再发布的窗口；Redis 没有独立持久化卷。自动运营验收必须覆盖消息对账与恢复，不能直接把强杀标记为安全暂停。

## 组件职责和状态保存

| 组件 | 职责与状态 | 权限边界 |
| --- | --- | --- |
| 夜间调度器 | 时间、阶段、deadline、互斥、每日额度和恢复后的续做；本地 SQLite 保存账本，重要动作前后落盘 | 不能直接凭模型文字判定发布成功 |
| Pi 阶段执行器 | 官方 RPC 接口启动短会话；分析、计划、开发、测试解释与后续归因 | 独立工作区，不持有生产管理员或 Docker socket 权限 |
| 数据读取工具 | 有时间窗、分页、查询超时的指标与正文读取；输出版本和样本身份 | 生产只读业务角色，不提供任意管理员 SQL |
| 模型预算入口 | 所有实测模型 HTTP 请求统一预扣、转发、结算和记录；覆盖重试与压缩 | 上游密钥由入口读取，模型和开发命令不读取凭据 |
| 测试与构建执行器 | 固定命令、独立服务和容器整体限额；测试与构建互斥 | 不能清理生产资源或扩大自身额度 |
| Git 与 PR 执行器 | 分支、push、PR、CI 状态和准确 SHA 合并 | 专用仓库权限，不 force push、不绕过规则 |
| 发布与备份执行器 | 校验候选和部署归属，备份、迁移、切换、健康验收、配对回执 | 固定受控入口持权；不接受任意 shell 字符串作为部署指令 |
| 独立恢复程序 | Pi 失联、超时或候选故障时释放重任务资源，恢复可用服务 | 无需模型预算；仍必须检查当前部署归属 |
| 通知执行器 | 日报、事故、去重、限次重试和发送回执 | 邮件内容来自实验记录，不让模型直接调用发送凭据 |

实验、日运行、发布使用各自的身份：`experiment_id` 可以跨日；`run_id` 对应一次日运行；`slice_id` 对应可部署步骤；`deployment_id` 对应一次真实发布。同一实验允许多次失败和修正，原始记录只追加，不被重跑覆盖。

账本保存阶段、操作意图、命令身份、产物哈希、会话文件、预算预留、现场版本和恢复动作。进程重启后先核对现实状态，再继续未完成阶段。会话恢复不能证明命令没有执行，也不能证明外部模型没有收费。

Pi RPC 的 `prompt` 成功只代表接受；以事件、`agent_settled`、实际产物和执行回执判断阶段结果。预算中止先清队列再 abort，并等待有界退出。保留完整会话，跨阶段传递摘要与证据索引，跨日状态以实验账本为准。

预算入口和发布策略属于模型不可改写的执行域。Pi、业务实验与测试环境不挂载真实 `.env`，不继承网站、数据库管理员或上游模型凭据；开发命令只在隔离执行器运行。模型出站仅允许预算入口，依赖下载和 Git 操作由列明目的地的专用工具执行。标准 shell、MCP 等入口要么禁用，要么替换为该执行器，不能绕回不受限宿主。启动验收包含直接 HTTP、脚本重试、嵌套调用、读取凭据和修改额度的反例；做不到此隔离时不启用付费自动流程。

## 每日运行和维护流程

白天只进行受限的指标采集、轻量分析和前一轮复核。需要大量 CPU、内存或隔离数据库的开发测试工作集中在维护窗口。Pi 不为每天发布而制造改动；没有充分理由时保存分析和计划，继续观察。

| 阶段 | 执行动作 | 完成条件与失败处理 |
| --- | --- | --- |
| 进入维护 | 02:00 显示维护页，拒绝新增生成与续跑，记录在途和排队任务 | 维护状态与业务健康分开，避免把预期停 Worker 当作意外故障 |
| 收尾与暂停 | 初始收尾预算 15 分钟；请求维护暂停，由 Worker 在可恢复点确认 | 暂停须取得下表确认；不能确认时取消本轮候选路径，恢复原服务并对账，不进入重任务或发布 |
| 更新前备份 | 活动业务写入静默后生成 PRE，记录暂停任务、旧镜像和部署身份 | 失败禁止候选发布，但不阻止恢复当前服务 |
| 分析与计划 | 读取数据快照，核对既有假设和所有者变更，形成一个小步计划 | 基线变化使有关证据过期时重新分析；不能直接沿用昨天计划 |
| 开发与验证 | 在实验分支开发，依次运行针对性检查、必要全量回归和固定案例对照 | 测试失败自主诊断；资源或费用上限耗尽时保存进度 |
| Git 与构建 | 留存分支与 PR，核验准确提交，串行构建 Python 和 Caddy 候选镜像 | Git、CI、镜像版本绑定；CI 排队不能延长维护窗口 |
| 发布与验收 | 核对人工部署和现场身份，执行兼容迁移与切换，检查服务和合成业务探针 | 候选 Worker 保持维护消费屏障；发现新人工版本立即使旧候选失效 |
| 更新后备份 | 健康候选生成 POST，与 PRE、部署和镜像配对 | POST 失败标记待补，不无限延长维护；下次普通发布前先偿还备份缺口 |
| 准备复核 | 建立候选版本的指标窗口、固定案例与下一次检查条件 | 不用自然日强行代替实际版本窗口 |
| 恢复开放 | 05:30 停止新候选路径，最迟 06:00 验证已知健康版本、解除维护并安全续跑任务 | 候选未完成则恢复适用稳定版；Pi 继续保存的诊断和实验 |

05:30 是首轮实测的收尾起点，按实际恢复耗时可提前。06:00 是开放目标，不允许 Pi 自行延后。新候选提前完成后仍保留约定维护时间；计划外事故若无法恢复，更新维护状态并真实告警，不能报告已开放。

每日 PRE 同时承担日常备份；没有发布时不强制制作重复 POST。独立程序检查日备份缺口，但使用相同备份锁和唯一执行入口，不另设无条件重复 dump。原 03:17 触发器只在接管验证后替换。

数据库、Redis、RabbitMQ 和维护入口在维护期间保留；主要释放 API 与 Worker。不要使用 `down -v`。维护页必须独立于候选前端构建结果，候选 Caddy 重建失败时仍能显示；保留证书卷和原可用入口。

维护消费屏障持久保存，不以易丢失的 Redis 标志作为唯一依据。Worker 启动后可以报心跳，但屏障存在时不能认领或执行生产消息；排队、延迟及未物化消息仍保留。候选验收使用独立数据库、Redis 与队列的合成探针。POST 已完成或登记待补、开放条件成立后，当前维护所有者先对账，再解除屏障和续跑；无法确认维护状态时不抢跑消息。

| 任务类型 | 暂停确认与恢复验收 |
| --- | --- |
| 单章与短篇 | 在已完成节点边界保存状态、待执行动作与调用回执，确认没有在途写事务；模型/工具中途结束记录未知状态，不能只靠 HTTP 终止认定已暂停 |
| 批次与章节子图 | 同时记录父批次位置、子线程和当前节点；确认不会重跑已完成章节，不把章节边界守卫误当全部节点均可暂停 |
| 计划、审核、用户暂停与预算暂停 | 保留原等待原因，不自动确认、补额度或恢复用户主动暂停 |
| 未认领与正在交接的消息 | 核对 delivery/ACK、任务、checkpoint、操作回执与锁；不能因断开连接重投而重复创建任务 |

统一暂停回执包含维护 epoch、任务与执行 generation、checkpoint 身份、数据库事务结果、消息状态和锁处置。只恢复由本轮维护暂停且状态仍匹配的任务。无法确认安全点时保留 `interruption_unconfirmed` 和费用预留，禁止候选发布；有界停止旧执行后只由稳定版对账恢复，不把未知结果报告为无损暂停。

## 计划阶段的小步约束

开始改代码前，Pi 必须提交结构化计划，机器检查和另一次审查通过后才进入开发。审查不要求用户逐阶段确认；新增功能仍留给用户决定。

计划包含：目标指标、数据证据、可证伪假设、基线身份、范围与非目标、预期涉及文件、风险、预估变更量、验证路径、费用与时间预算、可独立部署步骤、旧版兼容性、恢复方法和次日复核条件。

目标必须给出可计算的最低改善量、严重退化条件、样本门槛和其他维度的保护条件，并在查看候选结果之前冻结。成本或速度实验不能以新增严重质量错误换取达标；不能测试完再移动门槛。已登记的基线缺口单列，不冒充通过，也不要求用本轮优化顺带修复全部历史缺口。

初始软目标为一个可证伪假设、一个业务行为变化，通常不超过 3 个生产文件与 150 行生产变更。大问题在计划阶段就拆成兼容、可验证的小步骤；不能每天部署半个消息协议。复杂步骤跨日留在分支完成后再发布。

执行兜底初值为每个部署步骤最多 8 个版本控制文件、300 行生产增删；测试和文档单独报告，不因触线删测试。检查覆盖整个步骤相对基线的累计变更，不能拆文件、拆提交或把生产逻辑移进测试目录绕过。锁文件、生成契约和大规模纯格式变化单列审查，不能静默排除其风险。

每天最多一次普通 Pi 发布；必要事故恢复与受控 revert 单独记录。一天多次修正可以在分支验证，但不为追指标反复上线。以下风险不由行数放行：鉴权、账费、并发、数据迁移、外部契约、部署与备份、依赖重大升级。自动流程不得修改自身预算、发布门槛和恢复策略。

这里的规模约束作用于运行中的 Pi 产品优化步骤。建立编排、隔离和恢复基础设施是单独审阅实施计划的初始化工程，不伪装成一天的小改动，也不通过 Pi 自己放宽规则来完成。

数据库自动变更限于已证明旧镜像兼容的扩展步骤。破坏性删除、不可逆迁移或新产品能力形成用户决策事项；Pi 继续其他已授权分析与维护工作。

发布还需证明 checkpoint、图节点、状态结构和队列 payload 的兼容。验证旧版暂停任务在候选继续，以及候选写过的状态在稳定版恢复；覆盖单章、短篇、批次、计划/审核等待和工具往返。不能证明时先排空受影响类型或禁止该候选发布；schema 兼容与 `/readyz` 不能代替此检查。

自动迁移必须设置锁等待与语句期限，明确事务提交/回滚回执和最晚开始时间。只允许在剩余维护时间内可安全取消、可核验结果的操作；非事务且不能安全取消的迁移不进入自动路径。人工意图到达后停止新增步骤，确认当前事务结果后交接。

## 数据分析和效果比较

快照记录真实部署、schema、配置、模型、提示词和评测规则版本；运行记录保存任务类型、实际模型、开始与结束时间、费用、token、重试、缓存、完成与失败状态。零值与缺失数据分开，不能补成真实费用或即时成功。

| 维度 | 首批指标 | 比较方式 |
| --- | --- | --- |
| 稳定性 | 完成率、失败/超时/降级/恢复次数、无消息任务、队列等待、可用性 | 分母包含计划执行但未成功的任务；暂停、人工等待和维护单列 |
| 成本 | 每个任务与每千输出字的估算费用、请求数、重试成本、缓存 | 同类型和模型配对，完整计入失败；供应商账单与估算分开 |
| 速度 | 首字等待、生成耗时、排队耗时、端到端耗时 | 节点耗时不含用户等待；分任务类型、上下文和输出规模 |
| 写作质量 | 约束满足、矛盾、重复、计划覆盖、必要信息保留、修订效果 | 固定案例规则检查与盲化语义评分分别报告 |
| 体验 | 核心流程成功、暂停恢复、错误可理解性、移动端展示 | 可重复浏览器场景、实际失败案例和用户反馈；不新增产品范围 |

发布前比较“当前用户更新后的基线”与“该基线加 Pi 步骤”，除计划明确声明的实验因素外，固定输入、模型、提示词与配置。提示词或配置本身是优化对象时，记录它的基线和候选版本，保证评测实际执行候选路径。固定数据哈希、保留失败和未知结果；机制替身测试不冒充真实模型质量。改动范围内所有受影响案例都执行，另用保留案例防止只对已见案例优化。

自动质量评审使用独立提示词、随机隐藏版本顺序和稳定 rubric，输出证据位置及理由。模型自报 pass 不算评分真值；同供应商评审有偏差，结果标记为自动评审，不冒充人工评审。规则严重错误不被平均文风得分抵消。

首轮配对最低 5 组案例，关键恢复场景全部覆盖。样本小，只有观察性结果，不能宣称统计显著或长篇质量整体提升。候选必须没有新增规则严重错误，受影响机制全部通过，盲评不出现重复的明显退化；结果冲突或证据不足时扩大评测或保存跨日任务，不强行发布。

次日线上数据按真实部署有效窗口聚合。同型完整任务少于 20 条时标记 `insufficient_evidence`，延长观察；尾部耗时样本不足 100 条时不以 p95 改善作为结论。这些是初始证据门槛，不是样本充分性的统计保证。固定配对实验用于补机制证据，日流量只提供线上关联证据。

观察期被人工部署、模型/配置变化或跨版本任务打断时标记 `confounded/mixed`，重新建立基线。变化可能来自用户、流量或服务供应商，不能把两天差异直接归给 Pi。

实验结果分为改善、未改善、明显退化、证据不足和基线已变化。未改善时自主检查样本、实现是否生效、混杂因素和假设是否被推翻，然后补证据或形成关联修正。相同基线与假设没有新证据时不重复改动。明显服务退化先恢复，随后继续原因分析。

## 用户开发部署与 Pi 的协作

分析、开发、测试和构建只在自己的分支与资源组中运行，不持有生产发布锁。用户随时可以开发、提交和提出部署意图；Pi 的维护流程不能阻止受控人工部署。

每个阶段前后检查远端 main、线上部署、schema、模型和配置。main 更新后合入实验分支，重新运行受影响检查；目标已被用户解决时结束该步骤，保存原因。存在冲突时继续诊断或跨日处理，不改写用户历史。

生产操作使用共同的发布入口。记录 `deployment_id`、单调递增 generation、owner、phase、各容器 image ID/digest、schema 与配置身份、预期当前版本、候选及最后健康版本。相同 commit 再部署也有不同身份，不能仅靠 SHA 判断归属。

人工部署意图优先：Pi 未发布步骤失效并保存进度；正在执行的有界生产步骤安全结束后交接，不把数据库迁移杀到一半。后续 Pi 命令和旧恢复程序必须在相同主机锁内校验当前 generation、owner 和实际容器身份。

恢复程序只能回滚仍由该 Pi 发布持有的候选。人工新版本出现后，旧 Pi 回滚意图失效。人工当前部署的恢复由它自己的发布记录决定，不使用 Pi 昨夜的旧基线。

维护另有持久 `maintenance_epoch`，在关闭入口或停止服务之前记录 owner、generation、deadline、进入维护时的部署与容器身份、已停服务、消费屏障和暂停回执。独立恢复分为“尚未发布时恢复原稳定服务并撤销维护”和“已发布时回滚自己仍持有的候选”；两条路径都在共同锁内核对维护与部署归属。Pi 在 PRE、分析或构建阶段失联也能走前一条路径。

人工接管在同一锁内继承维护状态、暂停任务和 06:00 开放责任，并使旧 epoch/token 失效；不能只换镜像而丢掉维护恢复责任。解除维护、解除消费屏障和任务续跑同样校验当前所有者，不让旧 watchdog 误恢复用户暂停或误开放人工正在维护的入口。

直接绕过入口执行 Docker 命令无法被该协议保证无竞争。检测现场与记录不一致时标记 `unknown`，取消旧自动写入意图，只读检查并报告；不能把未知镜像自行认领成 Pi 候选。锁过期也不证明旧 Docker 操作结束，接管前核验在途动作。

GitHub concurrency 只协调 Actions，不代替服务器锁。代码合并与上线分开记录；合并成功不等于线上已使用该版本。

## GitHub 流转

每个实验使用 `codex/pi/<experiment-id>` 工作分支，可跨日保存进度；可部署步骤使用 `codex/pi/<experiment-id>/<slice-id>` 独立候选分支和 PR。工作分支的后续 WIP 不推入 ready 候选。候选进入验收后冻结 head；任何新提交都撤销旧检查与自动合并意图，重新验证。步骤分支关联同一父实验，累计范围检查不能按分支拆分绕过。

Pi 自动 push 未完成进度，生成包含理由、范围、测试、费用和复核条件的 PR；未完成候选保持 draft。一个步骤完成后再从最新适用基线准备后续步骤，不能用同一 head 分支同时承载多个 ready PR。

主分支只合并检查通过且基线仍有效的准确 head SHA。仓库规则不能要求每次人工审核才能满足全自动目标，也不能给机器人绕过保护权限。必需检查须把未运行和环境跳过判为未验收，不能只因绿色摘要放行。

优先采用限定 Myink 仓库的 GitHub App 和短期 token，由凭据工具执行 Git/PR 操作。日常仅给予 Contents/Pull requests 写与检查状态读权限，不给予 Administration、Secrets、Workflows 或规则绕过权限；这些路径的更改进入单独政策流程。凭据配置是服务器启用条件，本机先用私有本地 bare remote 和模拟检查回执验证流转。

push、PR、CI、merge、build、deploy、rollback、compare 分别保存状态。部署目标绑定准确 merge commit 与候选镜像，不隐式部署“最新 main”。已合并的坏改动以新的 revert PR 修复历史，不 force push。

GitHub 保存代码、依赖锁、非秘密配置和不包含原始私密数据的报告；正文样本、数据库备份、账号数据、密钥和证书进入私有证据目录。

## 备份与恢复

PRE/POST manifest 包含运行和发布身份、phase、起止时间、PG/工具版本、数据库身份、代码与镜像、schema、大小、SHA-256、完整性、附件/角色/配置引用、离机复制及恢复演练状态。Pi 分析 manifest，不读取包含凭据材料的整个 dump。

每份备份验证 dump 退出码、非空、压缩完整性、哈希和 stderr；这些只证明基本产物完整。首次启用、迁移、备份工具变化后，以及每周一次，在独立 PG16+pgvector 完整恢复验证 schema、角色、RLS、关系、章节、checkpoint 和附件对应。恢复使用 `ON_ERROR_STOP`，不能忽略 SQL 错误。

恢复集合包括 PG 业务与任务数据、全局角色或重建材料、反馈附件、证书与必要运行配置、有效 `MODEL_CREDENTIAL_KEY`、稳定镜像及代码版本。数据库 dump 不覆盖这些全部内容。

保留至少 14 个自然日的完整日备份，最近 5 次发布的 PRE/POST 配对，以及当前稳定版恢复点；失败产物不挤占完整备份名额。保留稳定版与最近两个已验证镜像集合。容量达到磁盘门槛时只清理 manifest 允许的旧候选与缓存；不能删除生产卷或唯一稳定恢复点来腾空间。

备份目录位于代码工作区之外，并明确从 Git 与构建上下文排除。离机复制采用可配置的私有加密目的地和确认回执；本机睡眠时同步不可用，不能作为全天灾备保证。本机先验证本地独立目的地；真实目的地和凭据未配置时服务器启用检查不通过，不声称已具备整机故障恢复。

PRE 失败阻止发布。POST 失败在开放 deadline 前登记 `backup_pending`，先恢复健康服务，再受限补跑；欠账未清禁止下一次普通发布。单纯应用故障优先恢复镜像，不盲目还原 PRE 覆盖新业务数据。数据库损坏走独立事故恢复，先保存现场再选恢复点，默认不自动接受不可逆数据损失。

## 资源与执行期限

以下为本机受限实测的初始参数，通过峰值与故障测试后再确定服务器值；构建和完整测试互斥。新启用的生产调度不允许把测试 OOM 变成自动扩大额度。

| 资源 | 初始配置 |
| --- | --- |
| 宿主、生产 PG、维护入口、Redis/RabbitMQ 与备份余量 | 规划 1280MiB；实测维护与备份峰值，不给 PG 直接套此总上限 |
| Pi 和直接子进程 | 384MiB、单核 50% CPU；阶段命令进入独立执行资源组 |
| 整组测试或专用 BuildKit | 1536MiB、2 核，额外 swap 最多 256MiB |
| 宿主余量 | 保留约 512MiB；swap 不计入稳定可用内存 |
| 重任务启动门槛 | 宿主可用内存足以容纳预算并保留余量；可用磁盘至少为本轮新增峰值估算加 5GiB 保底 |
| 重任务中止门槛 | 可用内存连续 10 秒低于 512MiB、宿主 OOM、PG/维护页异常、期限或资源限额触发 |

专用 Buildx `docker-container` builder 配置内存、RAM+swap 合计、CPU 与 `max-parallelism=1`；明确指定 builder，依次 build/load 两镜像。`docker compose build --memory` 不支持 BuildKit，运行容器的 mem_limit 也不等于构建限额。核对真实 cgroup 子树和峰值，镜像加载、Docker daemon 与 CLI 开销计入宿主余量。

磁盘估算覆盖 PRE/POST 与临时产物、附件增量、候选和稳定镜像并存、BuildKit 冷缓存以及加载开销，采用最近实测峰值和保守余量。备份、构建、镜像加载前分别复核；未知峰值先在本机校准，不能仅凭还有 5GiB 就开始。

测试 runner 和测试 PG/Redis/RabbitMQ 必须共同受整组限额约束。只给 shell 设置上限不能约束 Docker daemon 启动的容器。测试禁用 xdist，前端 worker 初始设为 1；测试 PG 的 tmpfs 也有容量和内存限制。

Linux使用可核验的 cgroup/systemd；Windows Pi 进程树需要 Job Object 或独立 Linux 环境约束。现有 WSL 配置影响其他工作，不能为实测擅自改全局 `.wslconfig` 或执行 `wsl --shutdown`。新建环境的发行版磁盘与工具缓存也放 E 盘。

模型请求、工具命令、构建、备份、迁移和恢复各有绝对期限。参考初值：单模型请求 120 秒、普通工具 120 秒、备份 600 秒、整组回归 45 分钟、单镜像 45 分钟；所有阶段同时受剩余维护时间约束。单个构建成功不代表四小时能完成全部流程，冷缓存耗时是启用验收项。

## 模型配置与费用控制

当前平台配置统一从 `.env` 的 `PLATFORM_MODEL_API_KEY`、`PLATFORM_MODEL_BASE_URL`、`PLATFORM_MODEL_NAME`、`PLATFORM_MODEL_PROTOCOL` 读取。既有协议为 Anthropic，模型为 `deepseek-v4.1-flash`；请求地址沿用现有配置，不在仓库保存实际密钥。

Pi 与评测入口由受控适配器读取这组配置，评测不再把过期 `DEEPSEEK_API_KEY` 作为唯一入口。不能只将 Anthropic Key 填进旧 DeepSeek 客户端；协议、工具调用、关闭思考、流式终止和 usage 都需兼容性测试。网站正常额度及账号自备配置行为保持既有规则。

模型代理累计 Pi 推理、压缩、重试、兼容性探测、自动评审和业务实验请求。一次 Pi 进程包含多次请求，不按进程计数。预扣请求次数和保守最坏费用，再按完整 usage 结算；未知或中断请求保留预留，不按零计费。多进程、重启和恢复共享账本。

自定义服务单价必须来自该服务已确认的价格配置，不直接拿 DeepSeek 官方价格或 Pi 的默认零价当作真实单价。未配置可信单价时真实调用关闭，本机离线检查继续。估算上限不能代替供应商账单硬上限；共享账户余额可能同时被网站消耗，服务余额耗尽时仍可执行独立恢复。

每日阶段分配初值为分析 15、开发 45、模型实验 30、剩余重试储备 10 次；这是总额内的分配，不能另加 100。计划先估算，预算不足就缩小实验或跨日保存。实测的累计 100 次/10 元独立于未来每日重置规则，不能跨午夜绕过首轮授权。

模型预算耗尽仅暂停付费工作；指标采集、现场核对、恢复与日报继续。Pi 不把同一请求移到未记账的 SDK、脚本或网站账号中绕开额度。

## E 盘实测和验收

本机代码工作区使用当前 Codex 管理的 `pi-autonomy-design/Myink` worktree，分支为 `codex/pi-autonomy-design`。主工作区文件不修改；新运行工具使用 `E:/tools/myink-pi/`，其中分别存 runtime、包缓存、Pi 配置与会话、私有凭据引用和实验产物。安装时显式设置所有相关缓存与会话路径，禁止依赖默认用户目录。

实测候选固定为官方 Pi v1.1.0，包名 `@earendil-works/pi-coding-agent`，Node 至少 22.19；安装前核验官方包、锁文件和完整性信息。确需新 Node 或 Linux 环境时也放 E 盘，不更换本机已有系统运行时。固定版本与当前官方接口不兼容时先修正实施方案，不静默切换到 latest。

第一轮在本机完成，服务器只允许设计需要的只读核验，不安装 Pi、不改 cron、不执行候选部署。独立 Compose 项目、PG、Redis、RabbitMQ、网络和端口不能复用生产或其他 worktree 测试资源。现有固定 `myink-test` 入口不可与其他会话并发。

按以下顺序验证，各阶段保存命令、输出、版本、资源峰值、预算和失败记录：

1. **离线协议测试**：虚拟时钟执行 02:00 至 06:00 流程；验证备份顺序、唯一执行者、阶段恢复、版本归因、计划约束、预算跨日与多进程、邮件内容和发送去重。
2. **本机基础设施演练**：独立服务中验证队列与 checkpoint 暂停恢复、PRE/POST、完整数据库恢复、维护页、稳定镜像恢复；模拟候选失败和人工发布抢占。
3. **受限资源试验**：冷/热缓存串行构建与必要完整回归；采样宿主、cgroup/Job 峰值、CPU/IO/swap与 deadline，确认 PG 和维护页持续可用。
4. **真实 Pi 兼容性**：固定已核验版本，验证文本、工具调用、thinking 关闭、流式、usage、中止与显式会话恢复。密钥不进日志。
5. **有界自主开发**：Pi 针对隔离评测或运营脚本中的一个可复现小问题形成计划、开发、测试、提交到本地实验 remote、候选发布和报告；故障注入仅在隔离分支与服务，不能改线上制造样例。
6. **前后比较演练**：固定合成案例进行配对评测，注入人工版本与模型配置变化，确认不会误归因；重放失败/样本不足后的自主诊断和跨日修正。

真实 GitHub push/PR、邮件发送、腾讯云告警和线上修改作为后续启用阶段；本机先模拟这些副作用。配置真实目的地后做专门验收，不能把模拟发送或 bare remote 测试称为已接通云服务。

必须通过的故障场景：PRE 失败、POST 超时、模型 402/空响应/未知 usage、直接 HTTP 与嵌套调用绕预算、Pi 在候选发布前或后崩溃、重复调度、阶段操作完成但回执未写、候选 OOM、测试失败、Worker 重启时生产消费屏障、旧 checkpoint 续跑与回滚、主分支更新、人工同 SHA 重新部署与维护接管、旧 watchdog 到期、绕过入口的现场变更、05:30 收尾和 06:00 开放期限。

实验级停止条件：达到首轮累计额度、价格不可验证、触及生产资源、未知现场身份、关键恢复/权限检查失败或无法核验资源限额。保存证据，继续允许的离线分析；不扩大授权或把被阻塞检查报告为通过。

本机协议验收与服务器无人值守启用分别出具回执。后续服务器阶段在受控维护窗口校准真实底座、备份、冷缓存构建与加载峰值、cgroup 生效和稳定版恢复耗时；保留外部监控与当前可用恢复通道。任一项不满足就不启用无人值守，缩小工作或另行设计外部执行资源，不把 Windows/WSL 通过当作服务器容量证据。本轮不执行该阶段。

## 邮件日报与真实故障通知

日报由账本生成，包含真实部署身份、分析与假设、计划范围和实际变化、PR/commit、检查和跳过、配对结果及样本量、费用与未知预留、备份、发布/回滚、人工更新影响和次日任务。没有发布也说明原因；失败不可被后续成功覆盖。

邮件用独立通知入口和已配置发送服务，每日一封摘要，完整报告留在可访问的受控位置。收件人与发送凭据为运行配置；未配置时保存待发送报告，不声称已通知。本机使用邮件捕获服务验证，不发送真实邮件。

真实事故由腾讯云可观测平台或独立拨测通知，涵盖计划外不可用、PG 异常、开放超时、备份失败与宿主资源异常。维护期只屏蔽预期业务停机，不屏蔽 PG、维护页和到点未开放。事故通知独立于 Pi 所在主机，不能依赖故障代理自己发信。

告警信号分为维护页探针、06:00 后业务可用探针，以及 PG、备份、调度器向外部平台发送的状态与心跳。维护页能打开不代表 PG 正常；外部平台必须对超时未上报报警。启用验收覆盖“维护页正常但 PG 不可用”“备份失败”“整机不再上报”。状态出口不暴露数据库连接或正文，邮件日报不承担事故探测。

个人认证不把每日开发报告当作短信告警来绕过业务短信要求。初始方案为故障告警加邮件日报；自定义业务短信不作为首轮必需功能。

## 文档与维护约定

后续实现建立 `ops/pi/` 的非秘密政策、阶段提示、少量扩展与受控入口；运行状态、正文和备份在工作区外。阶段 Skill 指定输入、输出、失败分类、期限和证据要求，提示词不能替代机器权限与检查。

维护文档分别覆盖启动配置、实验与评分规范、发布与人工交接、故障恢复、备份演练、通知和升级 Pi。每次策略或提示词变化有版本与测试，Pi 不在正常优化中自行修改政策。官方升级固定版本、先跑兼容演练，不能自动跟随 latest。

第一轮成功必须同时满足：主工作区和生产资源未变、授权额度内、资源约束实际生效、暂停恢复与独立回滚可复现、人工版本不被覆盖、基线变化正确分流、备份可恢复、小步计划先于开发、报告可追溯。只有模型能回复、Pi 能改文件或 CI 绿色，不足以启用无人值守服务器。
