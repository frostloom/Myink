# P2：任务总预算、暂停与恢复设计

状态：待用户审阅；尚未开始产品代码实现。

## 目标与已确认行为

用户希望在账号的「全局环境配置」中自由设置任务预算。每次章节生成、批次生成或短篇生成使用自己的预算快照，累计计算整个 Agent 流程的模型请求、估算费用和运行时间。触及任一上限后自动暂停、保留成果，由用户追加预算后手动继续；不会自动追加或清零消耗。用户已授权验收后的 GitHub 推送与线上部署。

### 配置与显示

- 「全局环境配置 → 任务预算」提供最大请求次数、最大估算费用（元）、最大累计运行时间（分钟）；接口时间单位为秒。
- 建议新任务默认值为 **100 次、5 元、30 分钟**；三个维度各自可设为 0，表示不限制该维度。这是本设计的默认值建议，尚需本次文档审阅确认。
- 配置属于当前账号，不是全站所有用户共用的额度。部署方已有每日额度仍独立生效，追加任务预算不能绕过每日额度、权限或并发约束。
- 请求次数必须为非负整数；费用和时间必须有限、非负。费用最多 6 位小数，接口运行秒数为整数；拒绝布尔值冒充整数、NaN、Infinity、负数和无法解析的值。
- 服务端在可信入队入口读取账号设置并生成任务预算快照；不接受普通生成请求或队列重投随意覆盖快照。修改账号默认值只影响随后新建的任务。
- 已存在且没有预算快照的任务按旧行为运行，避免升级突然中止存量任务。CLI 新任务使用同样的部署默认值；不借用其他用户的账号配置。
- 任务详情与历史显示上限、累计已用、未确认费用预留、当前阶段及暂停原因。文案明确费用是估算，不是供应商账单。

### 预算覆盖范围

- 第一版覆盖队列任务 `chapter_generate`、`batch_generate`、`short_generate`，及其续跑路径。批次子线程共享父任务额度，不能每章重新获得额度。
- 规划、正文、工具驱动的后续模型请求、抽取、规则后的模型审核、改稿、摘要、批次审计和 Reflexion 都属于该任务。工具自身的非模型调用不计入模型请求次数，但消耗运行时间。
- HTTP 重试、流式重试、主模型失败后的备用模型请求都各算一次。不能把一个节点调用误算成一次实际网络请求。
- SDK 内置重试必须在受预算管理的调用中禁用，重试统一由可记账的显式尝试控制，避免隐藏请求绕过次数上限。
- 建书聊天、文风提取、连接探测等没有任务 ID 的账号级调用继续使用现有准入机制，不伪造任务，也不扩大本轮范围。

## 已发现的现状与风险

- `environment.py`、`routes_environment.py` 和 `EnvironmentPage.tsx` 已提供账号级配置读写。
- `worker/enqueue.py` 是当前唯一入队实现，原 Go 网关已经退场；没有必要为此恢复或重构 Go 网关。
- `model_admission.py` 处理账号级调用的每日额度，不能直接替代任务生命周期预算。
- 长篇图使用持久化检查点，但 `resume_thread` 当前合并快照后传入新的状态重新 invoke；代码中已有「从 START 重跑」的说明。必须实际验证并修正预算恢复路径，不能只凭检查点存在宣称不会重跑。
- 短篇 `short_runner.py` 是普通函数，已有稿件恢复机制，但不是每阶段持久化。补写、审稿、改稿之间仍需要明确恢复位置。
- Provider 自行重试，若仅在 `_bounded_generate` 外计数，会漏掉真实 HTTP 尝试。节点内还有异常吞并和降级逻辑，预算暂停必须单独传播，不能变成模型失败后自动重试。
- 一个节点内部可能多次调用模型；节点中途暂停时，仅恢复节点会重复付费。需要保留已经成功返回的调用结果并在恢复时复用。

## 方案选择

1. 仅在节点结束后聚合 `AgentRun`：实现简单，但无法阻止下一次请求、漏算隐藏重试，也不能解决节点中途恢复。**不采用。**
2. 仅靠 Redis 计数：并发预留方便，但数据过期、重启和旧消息重投可能丢失任务累计值，难以对齐持久化进度。**不作为权威存储。**
3. **采用 PostgreSQL 持久账本与请求前预留，复用既有图检查点和任务状态。** Redis 仍服务现有队列、心跳和 SSE，不新增调度系统。

## 数据与调用边界

### 任务预算账本

以根任务 ID 为唯一归属，保存版本、配置快照、累计请求次数、已确认估算费用、未确认预留费用、累计运行秒数、执行所有者和暂停原因。预算写入与请求预留使用独立短事务和行锁，不与章节正文的长事务绑定；业务事务回滚不撤销已经发生的请求消耗。

预算数据必须能跨 Worker 重启和消息重投保留。活动执行使用带所有者的租约；只有当前持有者可以推进计时、结算和暂停状态。租约失效后的旧 Worker 不得继续发新请求或覆盖新执行者状态。累计时间包含执行中的工具和重试退避，排队与人工暂停等待不计入；重启不能把累计时间清零。

账本的查询和修改沿用任务归属校验；新增表或字段必须纳入项目现有初始化/幂等升级入口、权限设置和清理策略。不能通过未校验所有者的预算端点泄露稿件或跨账号修改额度。

### 一次实际请求

1. 检查根任务、执行租约和剩余运行时间。
2. 以行锁原子确认次数余量和费用余量；根据当前模型价格、保守输入估算与输出上限预留本次费用，同时消耗一次请求配额。
3. 余量不够时，不发送请求，记录 `request_limit`、`cost_limit` 或 `time_limit` 并转入可恢复暂停。
4. 实际超时不得超过剩余运行时间；已发出的请求无法保证上游立刻取消，边界可能存在在途费用。
5. 收到响应后立即持久化响应结果与用量，再进行应用层解析。返回用量完整时以估算实际消耗结算；失败、断流、缺失用量或结果不明时保守保留费用预留，明确标记未确认，不能当成免费。
6. 使用原定价表或用户连接的自定义价格。未知价格模型使用正数保守估算；不能以零价格绕过已开启的费用限制。

请求预算异常应独立于网络异常，不被 Provider、fallback chain、节点摘要/复盘的兜底逻辑吞掉，不触发自动网络重试或备用模型调用。预算存储不可用时不再发送付费请求，保留现场并给出基础设施错误。

## 暂停、检查点与恢复

### 可复用的调用成果

为任务内每个逻辑模型调用保存稳定的阶段/调用位置、输入摘要、模型引用、完整返回结果和结算收据。只保存恢复需要的数据，不存 API Key、Authorization、请求头或重复的完整输入提示词。数据通过根任务归属保护，并跟随任务清理。

恢复遇到已完成且输入摘要一致的逻辑调用时复用结果，不再次计费；输入或模型配置变化不得错误复用。供应商已执行但进程在返回成果落库前崩溃的情况无法承诺恰好一次，保留不确定预留并在界面说明，不偷偷退款或宣称完全无重复。

### 长篇和批次

- 保持同一根任务 ID 和图 thread ID，预算暂停保留已完成节点的状态与成果。
- 验证 LangGraph 当前版本的异常中断、动态 interrupt 和正确恢复输入；预算恢复使用能从未完成位置继续的路径，不将整个旧状态作为新的图输入重启。
- 节点中途暂停时可重新进入该节点，但此前完成的模型调用由成果账本复用；已落库的章节、记忆和进度不得再次覆盖、重复插入或重复提取。
- 批次已完成章不重跑，当前未完成章继续，批次审核和 Reflexion 仍计入同一预算。
- 兼容现有 `awaiting_plan`、`awaiting_review`、手动暂停与取消；预算耗尽不会伪装成人工审稿需求或覆盖取消状态。

### 短篇

- 为成稿、补写、审稿、改稿和最终落库保留明确的完成位置与成果。
- 已成功成稿但审稿前超预算时，恢复只进行审稿；审稿已完成但改稿前超预算时，恢复使用同一审稿结论进入改稿。
- 不把完整稿件藏在只用于观测的 SSE 中；服务重启后仍可恢复。
- 保持短篇与长篇一致性检查系统的既有边界，不为短篇引入长篇记忆抽取和跨章校验。

### 追加预算

复用任务恢复操作，增加可选的请求次数、费用、运行秒数追加量。追加量为非负、有限值；有额度限制的维度提升其累计上限，已用值从不减少。普通「继续」不自动追加；仍没有余量时返回可理解的提示，任务保持暂停。

追加与状态转移在同一个带任务行锁的事务中完成，并通过操作幂等标识防止双击、超时重试或多标签页重复增加额度、重复发布。队列发布确定失败与结果不明沿用项目的补偿/幂等原则，不凭空扣两次或重复获得预算。取消、已完成和其他账号的任务不得追加并恢复。

## 前端与 API 契约

- 环境配置增加 `task_budget`，省略时保留现值，明确提交时校验并更新；响应始终给出有效配置。
- 任务详情和列表增加结构化预算状态；预算暂停仍使用 `paused`，通过暂停原因区分手动暂停。
- 任务预算暂停面板展示已用/上限、阶段、停止原因、未确认预留费用，并提供「追加预算并继续」。单项无上限时显示「不限」。
- SSE 只传必要预算元数据，刷新页面通过 API 读取权威状态，不依赖仍在内存的事件。
- 更新 `spec/api-openapi.json` 与 TypeScript 类型；老客户端未传预算字段仍能读写已有配置。
- 沿用已有页面布局与样式，不做无关 UI 重构。

## 验收与测试

采用 Superpowers 测试先行：先写失败测试、确认失败原因，再实现最小改动。生产功能不得通过真实付费模型测试作为唯一验收依据。

1. 配置：默认值、部分更新、0 表示不限、负数/NaN/Infinity/布尔值拒绝、账号隔离、快照不随默认修改。
2. 请求次数：恰好达到上限、下一次被拦截且没有 HTTP、重试/fallback/流式计数、SDK 隐藏重试禁用、批次子任务共享上限。
3. 费用：发前预留、用量结算、未知模型、失败/断流保留预留、价格非法拒绝、费用精度与边界、在途异常结果不明。
4. 时间：累计执行、排队/暂停不计、重启保留时间、请求超时受剩余时间限制、旧租约持有者不能继续调用。
5. 持久性：并发预留、重复消息、账本不可用不发请求、业务事务回滚不抹消耗、成功结果复用、输入变化不复用。
6. 恢复：单章中途、工具循环中途、批次中间章、短篇审稿/改稿前暂停；恢复不重跑已完成调用、不重复落库；兼容人工计划与审稿。
7. API：所有者校验、已终态不可恢复、追加幂等、双击恢复、发布失败与结果不明、历史任务兼容。
8. 前端：配置保存/校验、暂停原因、单位转换、追加表单、失败提示、操作中防重复、刷新后状态一致；桌面及 390px 窄屏实际浏览器检查。

最终执行 Python 全量回归、前端 lint/test/build、API 契约差异检查和镜像构建，集成测试使用隔离 PostgreSQL、Redis、RabbitMQ。`myink-test` 固定端口不能跨会话并行使用；不碰生产库做测试。记录 xfail、skip 和阻塞，不能把跳过当通过。只有涉及实际 Go 代码才运行其对应检查。
