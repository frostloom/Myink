# Pi 合入 main 与管理员控制台

用户授权本轮将 Pi 合入 main，并在 main 管理台查看 Pi 运行状况、指标判断与迭代记录，选择是否发布已准备的候选。沿用此前连续推进、无需逐阶段确认的约定。生产部署仍须单独针对精确产物授权；后台中的发布按钮是未来每一候选的人工授权入口。

## 产品行为

现有 Vue 后台增加 `/admin/pi`。上部显示真实宿主状态、当前周期/部署和观察时间；指标区明确区分采样数量、证据不足、主机事实与模型建议。记录区按运行/日期浏览分析、工具、开发、失败、测试、版本、变更范围及次日计划，保留 null/unknown。管理员可查看精确候选摘要、文件差异与冻结检查；确认对话框明确将发布的镜像及候选。选择暂不发布仅留下决定，持久门禁继续等待；批准发布异步返回操作ID，只有实际部署核验后显示成功。重复点击或网络重试不产生重复部署；中断操作保留 uncertain，不能自动重放。

设计决定：复用当前 Vue 布局、颜色、表格和原生对话框，不新增前端框架。管理员入口与 Pi 工具严格分开；六项模型工具不增加管理员能力。

## 主机边界

产品 API 复用真实 require_admin、逐请求审计和 no-store；无管理员身份、降权、审计写失败均不得访问 Pi 数据或发起动作。API 通过固定 Unix socket 和私有服务凭据调用宿主桥接。浏览器仅提供周期、精确候选摘要、请求UUID和 publish/defer；不能提供路径、命令、环境变量、任意SQL或镜像标签。产品容器不挂 Docker socket、原费用/manager库或root配置。

宿主桥接读取原 ApprovalGate 和验证后的 AuditReader，状态与事件白名单投影。发布命令元数据仅记录人工请求/幂等/结果，不建立第二个 Pi 管理器或费用账本。执行与 nightly 使用同一锁。root在执行前重新校验当前周期和全部候选摘要；由真实管理员点击产生精确 human_operator 收据，然后复用同一门禁和原生部署核验。

发布器只使用当前周期冻结的 Python-only 镜像和root准备的固定部署材料；保留现有配置、依赖、数据卷及 API/worker 数量，不构建/拉取任意镜像，不迁移schema。发布前业务队列必须为空、基线/配置/镜像/源码证明未漂移，发布后核对物理运行版本并由原确认器进入 observing。失败保留阶段意图和审计。候选Git对象以root受信任源码材料核对完整包后建立，不能用基线提交冒充修改后源码；没有完整来源或发布材料则显示不可发布的原因。发布镜像与GitHub源码同步分别留证，本轮控制台不凭服务凭据获得任意Git推送能力。

宿主服务、socket、凭据和只读源码材料通过部署说明/固定systemd配置安装，默认未配置时 API 明确不可用。当前请求先完成代码、合并、测试及推送，不自动把新的管理台镜像部署生产，不触发当前observing周期的再次发布或真实模型请求。

## 验收

- 保留 main 最新写作/VIP/Vue 功能，合并冲突逐项处理，保护全部旧未提交文件。
- 后端测试真实管理员身份边界、审计失败、输出脱敏、数据损坏/宿主不可用、分页日期、动作闭合输入和幂等。
- 宿主测试精确候选绑定、延后不授权、批准/部署/核验真实顺序、并发与重启不重放、旧基线及繁忙队列拒绝、费用/manager逻辑摘要不变。
- Vue 测试显示证据不足、选择运行、跨天计划、候选确认、延后、异步进度、失败与权限撤销；真实浏览器验证桌面/窄屏和键盘交互。
- 按实际范围完成 Pi 离线、Python隔离全量、前端 lint/test/build、镜像/三浏览器CI；环境未运行/被排除的检查如实记录。
