# 管理员默认配置与用户高级设置

日期：2026-10-20
状态：设计草案，待用户确认；未实现。
分支：codex/admin-control-plane。

## 已确认的目标

管理员提前配置大部分创作资源，普通用户无需配置即可创作。普通用户保留当前可调整偏好，入口收进高级设置，日常页面不展示具体配置。减少配置缺失、无效模型和请求失败；不能承诺外部供应商永不失败。遵循 Superpowers 的设计、计划、测试驱动开发、审查和验证流程。Hindsight 仅使用 myink 库。

## 当前实现依据

- platform_configuration.py 已集中管理连接、六个角色的模型路由、附加提示词和题材包；普通用户仅可选择已发布的 writer/planner 模型。
- EnvironmentPage.tsx 当前直接展示模型、思考模式、任务预算及扫榜配置。
- environment.py 的思考和扫榜默认值、task_budget.py 的预算默认值尚未统一使用管理员默认设置。
- 已有请求预算、限流、供应商重试、任务检查点与续跑机制；本轮优先复用。

## 建议的本轮范围

### 1. 平台默认设置

扩展现有平台配置单例，新增 user_defaults，包含 thinking_enabled、task_budget、rankings。模型默认路由继续使用 model_routes，不增加第二份路由来源。附加提示词和题材包沿用现有管理方式。

管理员可以设置上述默认值并保存。旧配置缺少 user_defaults 时，预算沿用现有 100 次请求、5 元、1800 秒；思考模式关闭；扫榜沿用当前部署默认值。配置升级不写入或覆盖用户已有偏好。

新增字段采用有默认值的兼容读取；老客户端省略 user_defaults 保存时保留现值，显式提交时按经过校验的字段更新。沿用现有版本号和 409 并发冲突保护，不独立维护版本。

### 2. 默认值与个人偏好的关系

每个可覆盖字段按“用户显式值 → 管理员默认 → 原有内置或部署默认”解析。false、0 和空模型选择有明确含义，不能用真假判断代替字段是否存在。模型空选择代表跟随平台默认，预算 0 保留现有不限语义。

已有用户保存过的偏好继续生效。未保存覆盖的用户跟随管理员更新；新任务在创建时记录生效预算，已运行或暂停任务继续使用现有预算快照。题材快照规则保持现状。

高级设置提供恢复平台默认的操作，仅删除对应偏好覆盖；不复制当前默认值到用户记录。恢复不清除账号其他配置或作品数据。服务端返回有效值及覆盖状态，前端不自行推断是否继承。

用户高级偏好不改变平台总成本、配额和权限限制。后台抽取、校验等模型继续按管理员路由运行。

### 3. 用户界面

保留 /environment 路径兼容已有链接，现有入口文案统一为高级设置。页面初次进入时配置区域折叠，主动展开后才能看到和调整模型、思考模式、预算及扫榜偏好；每次重新进入默认折叠，不用自动弹窗或引导要求用户配置。

常规创作页面保留题材、梗概、章节目标等创作输入，不展示连接地址、密钥、模型角色与预算技术参数。已有高级设置保存能力保留；新增恢复默认及当前使用平台默认/个人设置的清晰说明。隐藏只是呈现方式，服务端权限照旧。

### 4. 配置与请求可靠性

增加管理员可查看的配置就绪检查，覆盖必要角色能否解析到启用连接、密钥能否解密、协议和地址是否合法、默认偏好是否合法。检查不回显凭据，不在加载页面或普通保存时自动发供应商请求。现有连接测试保留为管理员主动操作，并明确仅证明测试时的连通性。

新建付费生成请求和入队任务前，在共享服务中检查相关角色的本地配置；配置不完整时返回稳定错误码和可读提示，不提交注定无法运行的任务。worker 执行前仍重新解析并校验，处理入队后配置变化。检查是本地配置检查，不把历史探针成功当成持续可用保证，也不要求所有角色每次重新联网探测。

先枚举本轮涉及的建书对话、规划、短篇提交、长篇单章和批次入口，对照实际角色调用确定检查范围。普通用户只看到平台暂不可用及重试建议，管理员看到具体待处理项。禁止向普通用户暴露端点、内部角色或凭据。

检查现有超时、429、5xx 和流式中断的行为，优先补针对性回归和明确的错误映射。保持现有重试预算；认证失败、无效请求和权限错误不盲目重试，不自动切到未经管理员指定的供应商。对可能已扣费或已经部分生成的操作，不在前端自动重复提交。保留现有输入、检查点与任务续跑能力。

## 本轮不包含

不新增用户自备连接权限，不将高级设置重新变为 API Key 编辑器。不开发账号角色管理、计费套餐、自动跨供应商故障转移或 Pi 功能。不合并 main、不部署，不使用真实生产库验收。真实供应商付费请求另行取得明确授权，默认用隔离数据库和协议替身验证。

## 验收与实现约束

- 新用户不打开高级设置即可使用完整默认配置走通创作链。
- 未覆盖字段跟随平台更新，显式覆盖和历史偏好保留，逐项恢复默认生效。
- false/0、局部覆盖、旧配置与并发保存有回归测试。
- 普通页面不展示高级配置，默认折叠可用键盘展开，修改与恢复默认可操作。
- 缺失或不可解密连接在请求/入队前被明确拒绝，用户消息不泄露内部信息。
- 超时、限流、流式中断的验证不重复创建任务或抹掉已保存内容。
- Python 相关测试、前端相关测试及 lint/build、API 契约检查和浏览器完整操作链按实际范围运行；完整集成验证使用独立服务和端口，记录所有跳过与环境阻塞。
- 实现前编写分步计划；先写有意义的失败回归，再实现，最后独立审查。
- 当前只编写设计，无业务代码修改，不自动提交、推送、合并或部署。

上述界面组织、字段级继承和本地就绪检查是本次建议，尚不视为用户已逐项批准。具体组件划分、辅助函数与测试分组由实现计划决定，保持 React/FastAPI 现有技术栈，不增加依赖。
