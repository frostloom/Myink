# 记忆与恢复边界修复

用户授权继续修复审查确认的四项 P2，沿用 main 逐项验证、提交、推送，不部署。

1. 已落库的文本记忆发生数值、否定、主体或条款变化时，必须生成待审增删，不能因子串/相似度返回 no_op。仅空白和句末标点变化可不变；不再自动猜测不同措辞是否同义，代价是可能增加待审项，已有记忆仍须人工确认才改变。
2. 同章重复校正同提案时，置信度或来源元数据变化不得增加重复待审项；并发校正也应串行化判重。保留已删除记忆可恢复、未被替代的明确拒绝仍有效。
3. 重写中间章时，后续仍保留的有限期或明确删除关系必须阻止更早关系复活。级联删除后可以恢复最新适用保留关系，同章版本和重复失效仍安全。
4. 审核摘要预算暂停后若用户恢复了历史版本，续跑不能把旧稿摘要覆盖到恢复后的正文。生成摘要期间正文发生变化也不能写回旧结果；正文未变的正常续跑仍应完成。

测试使用独立 Docker 项目和空闲端口，不能连接默认/生产服务。保护 .DS_Store，不改变 Pi、后台分支和部署配置。
