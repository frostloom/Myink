# 本机 Pi 管理器：持久队列与可追溯工程指标

用户要求继续持续管理开发，并保留可用于简历的指标。沿用 Python 控制层、既有 Ledger、local_cycle 和 Pi 1.1.0；不修改上游 Pi 核心。用户已授权自主实施、真实模型和阶段推送，不逐步询问；main 合并、部署仍不在范围内。

本轮交付一层串行本机管理器：宿主将已固定、独立审查的 cycle 请求入队；管理器按优先级及入队顺序分派，在持久 intent 后才调用 local_cycle。真实执行仍保留选题/开发两次独立审查，不能把模型建议直接变成任务或期望测试。

状态分离：任务描述的注册成功是 done；执行另有稳定 dispatch 操作。执行完成后重启不再调用；pending/uncertain 执行使整个队列停止对账，不根据文件存在或进程消失猜成功。注册中断只允许宿主重新验证同一字节请求后完成注册，不能被当作可分派任务。已知 blocked/failed 停止本次批处理；后续显式调用可以处理其他独立任务，不重试旧任务。候选仍为 review_candidate，不自动采纳。

默认 status 完全只读，不创建 SQLite/lock/WAL。init 显式建立 700 父目录中的 600 独立状态文件，绑定原费用账本和运行模式；全程不改费用策略。串行锁覆盖整个批处理；队列、锁、SQLite sidecar 与各任务输入/输出/Docker socket/费用账本角色隔离，复用现有规范化路径规则。有限批处理最多20项、3600秒，deadline/取消传给原执行器。

指标按可证明来源记录：注册任务数、执行意图数、终态、对账停止、单次分派耗时及ACTUAL/SIMULATED。intent 数不是实际模型次数；费用/模型数据只引用原账本或真实执行报告，缺失为unknown。建立简历指标台账，将工程可靠性、执行效率和业务结果分开；没有同任务/版本/预算的配对试验不报效率提升百分比，实验覆盖不等于生产可用性。

验收：红绿测试；独立子进程重复启动、并发、intent后崩溃、执行后回执前崩溃、取消/期限、配置漂移与路径角色；实际原执行入口接线和持久重放；完整Pi回归。真实费用验收另以新runtime/身份/原账本/独立审查运行，禁止重放旧账本或复制审批。未做的真实长跑、线上可用性、吞吐提升明确留空。

实施判断：首版只接收已验证请求，不自动生成gold或恢复未知执行；减少管理权限扩散，代价是任务发现和未知对账仍需后续适配器。所有候选必须独立采纳，连续任务不意味着自动发布。

审查后的细化：同一原账本会在每轮结算后变化，ACTUAL只允许一个已封存待执行请求；后续任务由可信宿主按最新检查点完成独立审查，再向700私有inbox原子发布 `*.task.json`。manifest严格包含schema=`pi-manager-admission-v1`、task_id、request_path、request_sha256、priority、mode；收件箱不批准请求、不改旧签名、不复制费用账本。有限run可等待0–600秒新输入，未知执行阻断收件箱。模拟静态多任务不冒充真实连续执行。显式取消仅适用于未开始任务。

SQLite主文件、全部sidecar和锁在每次事务前校验普通单链接私有文件；callback返回后的终态写入也重新校验。恢复时检验登记/取消receipt及done dispatch的mode/binding/verified/摘要/耗时。每项耗时从分派回调入口到原执行器返回与产物校验，含审查等待；pending崩溃为unknown。批次耗时另记，不把两者混为性能提升。
