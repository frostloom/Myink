# Pi 真实试验只读预检

先交付可信宿主入口的只读前置阶段，识别当前累计账本和历史策略是否与宿主显式固定的身份一致。容器合成验收不能变为付费入口。用户要求自主推进、不提问，方案与执行由主代理决定。

使用 SQLite URI mode=ro、query_only 和单一读事务，复用 Ledger 的完整 schema/record 校验及原授权链校验；禁止调用 Ledger 构造器、设置 WAL 模式、创建 scope、预留、认领、清理未知费用或加载凭据。活动 WAL 必须可见，不能使用 immutable=1。SQLite 读连接可能维护 shm 读标记，因此只承诺无逻辑写入，不承诺所有 SQLite 辅助文件字节不变。

宿主必须提供原 scope 的 SHA256 和规范化 policy SHA256。输出包含同一快照的逻辑指纹（schema、operations、events）、总行数、累计请求数、已知费用、未知预留、保守占用/余额，以及 policy 所声明的 live 条件和单次最大输出的保守预留。不输出正文、授权引用、提供方请求 ID、完整策略、来源路径或密钥。无效账本、缺失/不完整授权、异常金额、身份漂移拒绝，不重建或修复。

本预检报告永远 paid_admission=false；scope 审计只证明所选账本内部授权链有效，不能证明调用者选择的是原账本，指纹也不是签名或锁。历史价格/校准声明不能升级为当前已验证事实。真实启动仍需独立复核当前价格及输入上界证据、冻结源码/配置/容器来源、明确本轮费用与绝对期限，并在原账本预留事务内再次核对；这阶段不实现网络 transport 或付费 launcher。

验证覆盖缺失/空/损坏/篡改账本、原授权链缺失或漂移、金额歧义/未知释放、活动 WAL 与并发写入的一致快照、读连接禁止写入、异常回执不泄露私有内容。运行原真实账本只读核对并保存无正文回执；付费请求数为0。
