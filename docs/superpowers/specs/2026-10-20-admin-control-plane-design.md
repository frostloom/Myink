# Admin control plane design

Date: 2026-10-20

## Intent and constraints
Separate administrator operations from novel writing. Preserve all existing admin reporting, users, tasks, writing analytics, invitations and feedback. Admin accounts land at /admin with a clean dedicated rail. Ordinary users write and select published models; they cannot configure endpoints, credentials, platform prompts or root genre packs. Existing main/pi refs and dirty original checkout remain untouched. Local work only; no push, merge or publish. User explicitly requested autonomous completion without questions, so design/plan review gates are replaced by documented assumptions and automated verification.

## Architecture
Persist a singleton platform configuration in the database (registered metadata and existing init/migration mechanism, application write permissions). Store encrypted model credentials using existing credentials helpers. Admin configuration API authenticates current admin role, audits writes and sends no-store responses. Keep reporting read-only sessions separate from configuration writes. Public catalog returns only id/name (no endpoints, credentials or internal prompts). Admin manages model connections with enabled and user_visible booleans, default backend role routes, additive role prompts, and overrides of existing root genre fields. Disabled models never execute; internal models may serve default roles but cannot be selected by users. Invalid/deleted/hidden saved selections fall back to platform role defaults rather than resurrect legacy user credentials. Before the first admin configuration save, deployment environment model settings remain a compatibility fallback, but legacy user/project connections are no longer consumed or exposed.

## API contract
GET/PUT /api/v1/admin/configuration
Response: {version:number, model_connections: Array<ModelConnection & {enabled:boolean,user_visible:boolean}>, model_routes:Record<string,string>, prompts:Record<string,string>, genre_packs:Record<string,GenreFields>}.
PUT accepts version for optimistic concurrency, full model_connections (api_key optional; omitted/blank preserves matching saved secret), model_routes, prompts, genre_packs. Routes use custom:<connection-id>. Empty objects/arrays intentionally clear respective configuration. A nonempty connection catalog requires an enabled writer default. Omitted planner/internal role defaults inherit the platform writer route, never the user writer selection; explicit per-role defaults override it. Deliberately saving no models disables generation, including the former deployment fallback. Genre overrides use existing pack IDs and field validation. No raw or encrypted key ever returned.
POST /api/v1/admin/configuration/models and /test-connection: existing ModelProbeRequest / response types, stored connection lookup from platform configuration only.
GET /api/v1/model-catalog returns {models:Array<{id:string,name:string}>, model_routes:Record<string,string>}; routes expose only user-visible IDs or empty/default. IDs in selections use custom:<id>.
GET /api/v1/environment retains compatibility fields model_connections:[] plus existing rankings/thinking/task_budget, adds available_models:Array<{id,name}>, model_routes contains user role selections only.
PUT /environment accepts model_routes selections to published enabled IDs, plus existing non-model preferences; model_connections rejected with 403 even empty explicit arrays. Legacy model probe routes require admin or reject. Project settings model writes rejected; project connection responses empty and old connections ignored. Root genre edits and restore endpoints reject ordinary writers. User genre field overrides on project creation must also be ignored/rejected, while selecting published genre pack remains available.

## Runtime
Both account-level and project-level provider resolution use platform connections exclusively. User selected writer/planner IDs override only roles supported by current settings; default backend role assignments handle extract, validation, audit and summary. Apply additive per-role system instructions to all model calls, preserving built-in structured output requirements and including additions in request budget checks. Genre get_root/catalog/build_book_pack read validated platform root overrides, preserving existing book snapshots. Conversational short creation resolves recognized genre names to the same root snapshots and keeps them on retries; unrecognized creative free-text genre remains allowed without a managed pack. Defaults stay usable before first admin save; database failures propagate rather than silently bypass policy.

## Verification
TDD focused service/API tests: ordinary users forbidden config writes/probes, public output has no secrets, encryption preservation, enabled/visible selection rules, disabled/deleted saved selections, optimistic save conflict, runtime account/project routing, prompts actually sent, root genre consumption and snapshots. Frontend interaction tests: admin independent navigation, configuration editing/loading/save errors, credential non-echo, user model-only selection and no connection editing, admin login home. Run focused suites then Python suite and frontend lint/test/build; record skips/environment failures honestly. Export OpenAPI contract and check drift. Final independent review before delivery.
