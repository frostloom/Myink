当前交付包含可复现的评测入口、已有真实模型记录、召回修复、故障恢复和浏览器证据。2026-10-08 用户决定只整理现有内容：本期不新增评审模型调用、生成重跑、真实 embedding 或 Reflexion 效果实验，不要求用户逐条人工复核。下列结果按现有证据介绍，未开展的效果验证作为局限保留。

| 成果 | 实际做了什么 | 可以说明什么 |
|---|---|---|
| 审核评测 | 20个固定合成案例、40条机制映射；原15例做过真实审核，暂定自动通过13/15、19/19引文逐字有效 | 有正反例、证据校验与失败保留；13/15不是已校准的语义准确率 |
| 召回优化 | 8例召回实验发现人物别名遗漏，最小修复后必要历史事件关键词命中4/7→6/7；这批未来章与跨租户泄漏均为0 | 能从失败定位到检索问题，再保留修复前后同任务证据；不是所有题材的普遍效果 |
| 生成与成本 | direct/full/no_hybrid两个任务各重复两次；99次真实请求，估算1.017986元，保留12个最终输出和16个总尝试 | 多阶段调用有共享预算、原始记录和仅补预算中止的机制；不是公平质量优劣结论 |
| 工具边界 | 工具执行预算、当前章缺省参数、失败后继续查证、服务端绑定项目id的回归 | 模型调用工具受编排层约束，不靠模型自觉遵守预算或租户权限 |
| 任务恢复 | 真实两worker环境杀掉持锁进程，重投由另一worker处理；重复消息没有重复persist，锁释放 | 能验证进程故障与重复投递下的持久状态；不宣称exactly-once或高负载可靠性 |

1. 打开下面的完整执行案例，展示“任务约束→生成→故障注入→拒绝→修订→落库一致”。错误由评测脚本注入，讲解时明确这一点。
2. 用 [召回修复前](../evaluations/p1-completion-2026-10-08/retrieval-before/summary.json) 和 [修复后](../evaluations/p1-completion-2026-10-08/retrieval-after/summary.json) 说明如何发现别名漏召回、修复和验证。
3. 打开 [生成与补跑报告](../evaluations/p1-completion-2026-10-08/comparison-combined/report.html)，展示完整正文、调用成本和保留的中止尝试。历史direct少前章尾文与明确别名映射，因此讲流程与成本，不讲系统质量胜出。
4. 用 [浏览器回执](../evaluations/p1-completion-2026-10-08/browser/receipt.json) 与 [验收记录](../evaluations/p1-completion-verification.md) 回答工程可靠性问题。

可以这样介绍：“这个项目处理连续创作中的历史约束、长任务恢复和作者反馈。我把生成、检索、审核、修订与落库串成可恢复的工作流，并建立了固定案例、工具边界、进程中断和浏览器验证。一次召回实验发现别名会遗漏必要历史，修复后同批任务命中从4/7到6/7；生成实验也保留预算中止和输入不公平的问题，结果可以追溯。”个人职责仍按实际经历说明。

当前没有经过独立校准的语义precision/recall、完整系统优于direct的公平结论、真实embedding质量或批次Reflexion收益。原质量字段保留pending/null，不把现有自动结构检查改名为人工确认。这些是当前材料的结论边界，不是本期必须继续执行的待办。

## 本轮完整案例（2026-10-08）

打开 [完整执行页面](agent-execution-live-2026-10-08.html)，先看初稿、人工反馈、修订稿和修改对比，再查看最终保存和运行过程。

- 数据：[本轮原始记录](../evaluations/workflow-recovery-2026-10-08-live.json)。
- 浏览器检查：[桌面与窄屏回执](../evaluations/interview-live-demo-browser.json)。
- 场景：现实题材、两名检修员、暴雨停电，林川左膝扭伤；全部为合成素材。
- 实际模型：`deepseek-v4-flash`，使用本地已有密钥，通过正常账号连接/角色路由调用，没有模型替身。
- 时间：2026-10-08 北京时间 18:07:41 至 18:08:49，约 69 秒（包括作品设置、生成、修订及导出）。
- 初稿 3389 字符，修订稿 3432 字符；20 条节点运行记录，输入 34549 / 输出 9130 tokens。
- 故障注入：脚本在初稿末尾加上“林川忽然获得了瞬间移动的超能力，眨眼就到了十公里外。”；调用实际候选拒绝接口，再走 `resolve_review` 的修订复审路径。不是模型自然生成的错误。
- 结果：问题句移除；最终审核 `pass`；`error=null`、`needs_review=false`；实际数据库正文与完整修订稿一致；被拒绝候选的审核记录有 `applied=true`。
- 保存：1 个章节、1 个旧版本、1 个拒绝候选、3 条事实、5 条事件、6 条人物状态。导出保留状态/失效字段，行数不代表所有行当前有效。
- 运行使用 Compose 项目 `myink-interview-live` 的临时 PostgreSQL 和 Redis；不使用开发或生产作品库，导出后清理。
- embedding 与排行榜关闭，向量索引/近邻检查有降级日志；不能用这个案例证明语义召回效果。单案例通过也不是长期质量评测。

完整初稿、输入修订的正文、修订结果和数据库产物从工作流状态/临时库导出；运行详情来自 `agent_runs`，其遥测字段仍可能有显式截断标记。
