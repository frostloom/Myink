# Myink 面试亮点与优化路线

更新：2026-10-08。面向 Agent 应用、平台工程和效果优化。这里跟踪面试准备与能力迭代；部署运维现状以 [REMAINING-WORK.md](REMAINING-WORK.md) 为准。旧 BACKLOG 是历史快照，不作为当前未完成清单。

## 项目介绍与亮点

Myink 面向连续小说创作，围绕长任务的上下文管理、生成一致性和恢复，组合持久化工作流、模型工具查证、分层记忆和审核修订，提供完整的前端与异步运行链路。

| 能力 | 代码/证据 | 面试应解释的取舍 |
|---|---|---|
| 批次图 + 单章图 | `workflow/batch_graph.py`、`chapter_graph.py`、`runner.py` | 固定流程提供可控边界；模型在工具与审核环节决定行为。不同等待/失败状态使用不同恢复入口 |
| 规则与模型联合审核 | `chapter_graph.route_after_audit`、`validation/ledger_l2.py` | 规则优先、证据引文守卫、修订预算；L2 仍有概率性误判风险 |
| 人工闭环 | `workflow/review.py`、`nodes.confirm_candidate` | 拒绝设定触发正文修订、重新抽取/校验；保留历史，处理旧候选 |
| 上下文工程 | `memory/recall.py`、`context_budget.py` | 三层记忆、人物状态、章节有效期、RRF、硬约束优先；token 是估算，向量默认关闭 |
| 工具与写入权限 | `workflow/tools.py`、`nodes._run_tool_loop` | 服务端绑定项目；工具只读，模型输出候选，编排层校验与写入 |
| 任务可靠性 | `worker/`、`workflow/checkpointer.py` | RabbitMQ 重投、Redis 锁/事件、PG 权威状态；不能宣称 exactly-once |
| 全栈交互 | `TaskTimeline.tsx`、`ChapterEditor.tsx`、`useTaskEvents.ts` | 增量事件、刷新恢复、409 版本保护、草稿隔离 |
| 可观测性与运维 | `models/runs.py`、`snapshot.py`、`pages/admin/`、部署记录 | 节点 usage/耗时/估算成本与选择性快照；备份/恢复和账号隔离属于工程证据 |

不要仅按文件数、测试数、Agent 角色数介绍项目。每个亮点准备一个问题、实现取舍、失败例子和验证入口。个人职责与第三方来源必须按实际经历填写，不从仓库推断个人贡献。

## P1：建立可量化的优化闭环

实施设计见 [评测体系设计与维护约定](EVALUATION-DESIGN.md)，操作见 [评测维护说明](../evals/README.md)。已落地40条覆盖映射、20例审核数据、8例召回、2任务重复生成对照、真实worker中断检查与Chromium浏览器入口。首轮审核15请求；生成两轮99请求，保留全部尝试。详见 [剩余 P1 验收](evaluations/p1-completion-verification.md)。2026-10-08用户决定本期只整理现有内容，不新增实验、不要求逐条人工复核；工程与已有实验按该范围交付。未校准的语义指标、公平质量对照、真实embedding和Reflexion效果不作为已验证结论。

| ID | 迭代项 | 最小交付 / 验收 | 依赖 |
|---|---|---|---|
| P1-01 | 统一评测数据与配置 | 20–30 个精选任务，包含正反例、难例、恢复和工具场景；记录模型标识、prompt 哈希、参数、时间和源提交；开发/保留集分离 | P0 |
| P1-02 | 模块对照评测 | 直接生成 vs 完整系统；完整 vs 无混合召回；完整 vs 无 Reflexion；同输入重复运行，记录波动、失败与成本，不只挑成功案例 | P1-01 |
| P1-03 | 校准审核指标 | 分类别统计 precision/recall、误报、人工介入；逐字证据验证；人工抽查校准 judge，不把自评当客观真值 | P1-01 |
| P1-04 | 评测口径对齐 | 修正 `style_drift` 实际测卷偏移等名称错配；阴性缺机制不计有效验证；区分 L1 缺口与已有真实模型语义覆盖 | P1-01 |
| P1-05 | 召回质量基线 | 标注每任务必要历史事实；比较关键词/向量/RRF；量 Recall@K、无关占比、token、耗时、跨章/租户泄漏 | P1-01 |
| P1-06 | 基于失败的召回升级 | 按基线决定别名/剧情术语、BM25、事实检索或 reranker；逐项消融，质量与成本一起比较 | P1-05 |
| P1-07 | 工具行为评测 | 必要查证、参数正确性、错误恢复、重复调用、预算终止；模型自选路径可多解，验证结果而非固定调用序列 | P0-03、P1-01 |
| P1-08 | 故障恢复验收 | 隔离资源复现 provider 超时、worker 中断、消息重投、确认/取消/续跑、SSE 重连；检查持久状态、重复副作用、锁与额度释放 | P0 |
| P1-09 | 关键浏览器 E2E | 登录、计划确认、增量正文、人工拒绝、刷新恢复、409 冲突、窄屏；服务与模型替身使检查可重复 | P0 |

先有 P1-01 和基线，再决定实现下面的能力。真实模型调用另设实验费用上限；开始前确认环境、模型和费用范围，使用合成/授权数据和隔离库。

本日状态：P1-01/04/06 的本轮切片已交付（别名漏召回推动最小修复）；P1-07/08/09 有工具边界、SDK故障替身、真实worker重投与浏览器证据，但不是全部模型路径或部署故障矩阵。P1-02 保存 direct/full/no_hybrid 原始输出，历史direct缺前章尾文/明确别名映射，入口已修正；P1-03 有暂定自动判分，未作独立语义校准；P1-05 有关键词与向量替身机制基线。公平质量、真实embedding与批次Reflexion效果实验暂停，原待复核字段保持pending，不伪造确认。本期使用 [面试讲解入口](interview/README.md) 展示现有成果；后续是否扩展以新的用户指令为准。

## P2：根据证据补强系统

| ID | 优化 | 验收方向 |
|---|---|---|
| P2-01 | 任务级资源预算 | 对整任务累计调用、token/成本、deadline；区分节点轮次、请求窗口、账号日额度；达到预算后可解释停止并保存可恢复状态 |
| P2-02 | 长文一致性缺口 | 优先由失败例推动物品、经历、伏笔兑现、能力前置、归属的结构化抽取/校验；阴性配对，避免机械规则误伤合法变化 |
| P2-03 | 记忆生命周期 | 编辑/重写后的影响面、后续章提醒、重建状态和确认；测事实有效期与失效后召回，不擅自改写后续正文 |
| P2-04 | 精确预算与性能 | 按 provider 能力选择 tokenizer，保留估算降级；测硬约束膨胀、检索规模、提示缓存和快照存储成本 |
| P2-05 | 可观测性增强 | 在现有快照上串工具 span、路由原因、修订差异、版本/配置；选择性记录要显式标缺失；原始结果脱敏且不向普通用户暴露其他租户 |
| P2-06 | 运行容量 | 隔离压测队列等待、并发、TTFT、p50/p95、错误率、限流；用证据调整 worker，而不是凭副本数量声称高可用 |
| P2-07 | 部署与账号剩余项 | 跟进 REMAINING-WORK 的 CSP/令牌、拨测告警、冷启动；数据库迁移是既定取舍，扩展需求成立时再考虑版本化迁移链 |
| P2-08 | 作者效率 | 选段改写/差异预览、已有稿件导入、分节生成；先测编辑量、等待时间和记忆同步，避免只有新增页面 |

## 条件性探索

Jev/专用 judge、MCP 工具服务化、模型动态路由/多模型复核等只在评测证明当前瓶颈后立项。外部榜单目前用于建书灵感，不应在图和介绍中描述为生成节点的在线数据源。新增自主角色需证明减少错误或作者工作量，不能只增加调用开销。

## 面试交付包与推荐顺序

1. P0：可信介绍、历史执行案例、工具修复和流转图。
2. P1-01/02/03/05：评测闭环与质量/成本表；失败例推动迭代。
3. P1-07/08/09：Agent 行为、恢复与浏览器证据。
4. P2：按已量化瓶颈选切片，记录前后变化。

最后准备五分钟演示、三项设计取舍、两项真实失败分析，以及可以追溯到原始数据的数字。现有机制测试、历史真实模型 smoke、新对照实验结果分别标来源；未跑过的压力/长篇质量检查不得写成通过。
