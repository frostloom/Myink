## Confirmed findings

1. **[P2] Register feedback modal cleanup with Vue watch.** `web/vue/src/components/FeedbackWidget.vue:225` returns a function from the watcher as if it were React useEffect. Vue ignores this return. Opening feedback sets body overflow to hidden and installs document keydown; closing or unmounting never restores overflow/removes that listener. Repeated opens accumulate listeners. Reproduction `restores scrolling after closing feedback`: set preexisting overflow auto, open, close; expected auto, received hidden. Use the watch callback's onCleanup and test both close and account-boundary unmount.

2. **[P2] Read the current session token for style operations.** `web/vue/src/pages/StyleLibraryPage.vue:108` captures a scalar token once during setup. The App intentionally keeps this page mounted for same-account token renewal, so list/retry/extract/save/rename/remove continue using the expired token indefinitely. React recomputes that variable on rerender. Reproduction `uses a rotated same-account token for style retries`: mount old-token, let initial list fail, replace session with same user/new-token, click retry; expected new-token, received old-token. Read a computed/current token at operation dispatch and invalidate/restart relevant loads without losing the user's draft.

3. **[P2] Derive feedback lamp geometry reactively.** `web/vue/src/components/FeedbackWidget.vue:420` captures `LAMP_HANG[lamp.value]` once. The lamp SVG and hit button update when theme previews or saved lamp style change, while cord/beam/span CSS variables remain from the original lamp. Reproduction `updates lamp beam when theme preview changes`: cube→cone updates data-lamp but --beam remains 58%, expected46%. Put this lookup inside render or computed and cover changing all relevant geometry values.

4. **[P2] Skip protected style-library loading for anonymous visitors.** `web/vue/src/pages/StyleLibraryPage.vue:173` always invokes reload, and reload at line163 calls `styleLibraryApi.list(token)` even for session null/status anonymous. The shared authenticatedGet still performs fetch with empty credentials, so this contradicts the approved no-protected-mount-requests guest contract. Reproduction `does not load protected style library for guests`: truly null session still records list(''). Existing StyleLibraryPage.test currently mocks this call and asserts returned builtin data, masking the contract issue. Show a local guest empty/catalogue preview, with no authenticated request, and update this fixture to assert the boundary.

5. **[P2] Cancel attachment fetch/publishing on account UI disposal.** `web/vue/src/components/AttachmentChip.vue:19` awaits the shared binary helper without AbortSignal, lifecycle/account guard, or disposal cleanup, then navigates the preopened tab. The binary helper is a separate raw fetch and is not registered in abortRequestsForToken; unmounting feedback on logout/account switch does not stop it. Reproduction `does not publish an attachment response after its account UI unmounts`: click attachment, unmount, resolve bytes; the old component creates a blob URL and opens A's private attachment afterward, and never closes the pending tab. Add an AbortController + current/alive guard, close only pending blank tabs on disposal, and avoid invalidating a completed tab's media prematurely.
