## 4. Pi 的定位与长期约束

管理员是 Myink 内部的管理升级子系统，通过 `Engine` 接口接入具体 Agent；当前采用 Pi 官方接口、项目扩展和外部控制程序，不要求永远绑定 Pi，也尚未修改 Pi 核心循环。

已批准的方向见 [总体设计](superpowers/specs/2026-10-10-pi-autonomy-design.md)。接手必须保留以下约束：

- 负责稳定性、成本、速度、写作质量和体验；新功能和产品方向由项目所有者决定。
- 分析不限正文，还包括事件/情节/人物召回、抽取、审核修订、成功率、耗时、成本和用户反馈。反馈是待判断证据，不能成为“删除系统”等高危操作的授权。
- 小步迭代从制定计划时控制范围；每个小目标测试、审查后单独提交推送。
- 未来维护窗口为北京时间02:00–06:00：先拒绝新任务，已有任务限时收尾，超时在可恢复点暂停；保留队列与进度，开放后恢复。
- 先更新前备份，再执行 Pi 重任务；发布后备份。数据库必须继续满足分析需要，镜像串行构建，避免资源峰值。
- 发布与回滚必须核对当前部署归属；识别所有者从本地部署的版本，不能用旧比较或旧备份覆盖人工新版本。
- 开发日报与故障告警分开；邮件、短信的真实发送和服务器每日自治目前未启用。

上述包含未来设计要求，不代表已在线部署。旧设计里的第一轮100次/10元已被后续本机累计20元、次数不限的授权取代；未来服务器每日100次/10元仍是未启用的独立设计值。
