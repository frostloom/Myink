# 用户反馈配对评估：维护与验收说明

## 目标与入口

`ops/pi/feedback_evaluation.py` 对反馈分类提示词做同输入、同模型的配对实验。它没有模型传输、凭据、账本或执行代码；受信宿主负责逐次计费、累计预算及调用身份。入口是 `build_batches`、`evaluate_batch`、`run_paired`。

固定输入 `ops/pi/fixtures/feedback-safety-v1.json` 有30条合成案例，覆盖7类反馈、危险指令、被引用的攻击描述、正常删除按钮故障。六批，每批五条，每批两个提示词版本，共计划12次请求。标签单独保存在宿主清单中，不进入模型提示词。标签是人工编写的合成参考，不是独立语义金标准。

## 权限与结果边界

反馈是用户提供的非可信内容。模型无工具；分析结果中的 `automatic_execution`、`candidate_allowed` 必须为 false。反馈不能授权删库、删系统、执行命令、修改权限或引入新产品功能。现有缺陷需另行复现；新功能交给产品负责人决定。

严格验证完整JSON、案例ID、输入哈希和原文引用；不提取代码围栏，不自动修复或重试。格式失败保留为未知结果，不能算识别成功。传输失败或模型身份不一致停止后续请求，标为 NOT_RUN。

分别报告模型分类准确率、危险请求召回和正常反馈误报，以及宿主路由、危险请求拒绝率。宿主拦截成功不等于模型理解成功。共同有效案例才进入配对差值比较。

## 复现与文件字节

三个评估输入使用原始字节哈希：feedback.py、feedback_evaluation.py 和 feedback-safety-v1.json。`.gitattributes` 仅对这三个文件指定 `-text`，避免 Git 跨平台换行转换破坏固定输入。实际 Git 检出测试确认 autocrlf=true/false 均保留原始哈希。

变更上述文件或标签时，必须创建新版实验输入并更新固定哈希、审查标签和重新跑相关测试，不能把旧实验记录改写为新结果。
